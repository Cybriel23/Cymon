## 1. Risk Watch

### 1.1 Cisco October bundle: five CVSS 9.8 unauthenticated root RCEs on Nexus switches, a CVSS 10.0 in License On-Prem, and legacy releases that will never be fixed (NEW)

Cisco published its bundled advisories on **7 October at 16:00 GMT** (updated 8 October), and the aggregate is about **a dozen critical CVEs** across four product families. **The NX-OS set is the one to act on:** **five flaws rated CVSS 9.8** let a **remote, unauthenticated** attacker execute code **as root** or crash the device on **Nexus 3000 Series and Nexus 9000 Series switches in standalone NX-OS mode**. Each requires a specific feature to be enabled, which is the only thing standing between most estates and a trivially exploitable core switch: **CVE-2026-76471** (heap buffer overflow, **CWE-122**, via **NX-API** — disabled by default; check with **`show feature | include nxapi`**); **CVE-2026-76485**, **CVE-2026-76486** and **CVE-2026-76501** (via **NGOAM**, with 76486 additionally requiring **SRv6** or **NV Overlay** and 76501 requiring **SRv6**); and **CVE-2026-76465** (via **MPLS OAM** — disabled by default, and **not** affecting Nexus 9000 switches with Silicon One ASICs). A separate **NX-OS security hardening release** covers further issues including **CVE-2026-76455** (improper access control) and **CVE-2026-76459** (out-of-bounds write). **CVE-2026-76471 also affects UCS 6300 Series Fabric Interconnects** (CSCwu58579) through the **UCS Manager XML API**, which is **enabled by default and cannot be disabled without losing functionality** — there, exploitation needs valid low-privileged credentials, so Cisco reduces the impact rating to High; **fixed in 4.3(6j)**, and **releases 4.2 and earlier must migrate**. **Confirmed not vulnerable: Nexus 7000, Nexus 9000 in ACI mode, MDS 9000, Firepower 1000/2100/4100/9300, Secure Firewall 200/1200/3100/4200/6100, UCS 6400/6500/6600 and UCS X-Series Direct 9108 100G** — scope the change rather than over-rotating. **Cisco states there are no workarounds**, but offers two things that matter operationally: **disable NGOAM, NX-API or MPLS OAM if you do not use them**, and **temporary Live Protect shields are available for all five** for switches that cannot yet take an upgrade-and-reboot window. Treat shields as a bridge, not a fix. Separately, **Cisco License On-Prem** (formerly Smart Software Manager) carries **CVE-2026-76482** at **CVSS 10.0** (improper cryptographic signature verification), **CVE-2026-76480** at **9.8** (missing authentication for a critical function), **CVE-2026-76483** at **9.1** (insufficiently protected credentials) and **CVE-2026-76484** at **8.8** (code injection), plus **CVE-2026-20328** (unauthorised access, no authentication required) and **CVE-2026-76454** (unauthenticated DoS); **fixed in 10-202609**, **no workarounds**, and **releases still branded Smart Software Manager will not receive a patch at all** — those require migration, which is a project, not a maintenance window. **Cisco APIC** adds three criticals (**CVE-2026-76498**, **76499**, **76500** — improper access control, OS command injection, memory flaws), **Meraki** a hardening release led by **CVE-2026-76464** (buffer overflows and out-of-bounds writes), and **Cisco Finesse** a high-severity **SSRF (CVE-2026-20362)** that is **publicly disclosed**. **Cisco PSIRT is not aware of exploitation of any of these**, and the NX-OS flaws were **found in Cisco's own internal security testing**. **Action, in order: run the Cisco Software Checker against your actual running releases today — the advisories do not publish fixed NX-OS version strings and the Checker is the only authoritative mapping. Then, before the upgrade window, run `show feature` on every Nexus 3000/9000 and disable NGOAM, NX-API and MPLS OAM anywhere they are not in active use; that single command sequence removes the unauthenticated path on most estates in minutes, where the reboot will take weeks to schedule.** Apply Live Protect shields to anything that cannot be upgraded this cycle. **Patch License On-Prem to 10-202609 immediately and start the migration plan for any Smart Software Manager-branded deployment — a CVSS 10.0 signature-verification bypass on your licensing server is an unauthenticated foothold inside the management plane, and there is no future patch coming.** **Sources:** [Cisco advisory CVE-2026-76471](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-napi-rce-r2shwu2j) · [Cisco advance notification, 7 October bundle](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-notice-fBn58ELx) · [Cisco MPLS OAM advisory](https://sec.cloudapps.cisco.com/security/center/content/CiscoSecurityAdvisory/cisco-sa-moam-rce-uBTzYV7) · [BleepingComputer](https://www.bleepingcomputer.com/news/security/cisco-warns-of-critical-flaws-allowing-nexus-switch-takeover/) · [SecurityWeek](https://www.securityweek.com/cisco-patches-a-dozen-critical-vulnerabilities/) · [GBHackers](https://gbhackers.com/critical-cisco-nexus-switch-vulnerabilities/)

### 1.2 Shai-Hulud returns in npm `tensorlake@0.5.144`, now hunting AI coding-agent credentials and booby-trapped against token revocation (NEW, significant)

The **tensorlake** npm package — a TypeScript SDK — was published as **version 0.5.144** carrying a new variant of the self-propagating **Shai-Hulud** credential worm, linked to the **ChainDrop** campaign first documented in early August 2026 against hundreds of packages including **Keyv** and **Cacheable**. The timeline shows a **repository compromise, not a registry one**: a rogue commit (**`e90c47bbb208e99cac8aa678405b2133f6cb3f52`**) was pushed to the **main branch of `tensorlakeai/tensorlake` under a maintainer's name at 01:20 UTC on 7 October**, and **the repository's own release workflow published the package to npm the next day** — so the project's legitimate CI signed and shipped the malware. **Version 0.5.144 has been removed from npm.** Execution chain: a **`preinstall` hook** runs **`package/lib/setup.mjs`**, an obfuscated loader which executes the payload **`package/lib/Math_Symbol.js`** using the **Bun** runtime. It harvests **npm, GitHub and AWS tokens, SSH keys, `.env` files, crypto wallets, messaging-app data, and CI, Kubernetes and Vault credentials**, drops the **HackBrowserData** binary, exfiltrates, persists, and can run remotely supplied code. **Two features make this variant materially worse than its predecessors.** First, **it explicitly targets AI coding-agent configuration files for Claude, Cursor, Kiro, Windsurf and Zed**, and **writes `.claude/settings.json` and `.vscode/tasks.json` into every reachable repository so that the payload re-executes whenever a developer opens that project in Claude Code or VS Code** — persistence that survives cleaning the node_modules tree and spreads by ordinary developer behaviour. Second, a **"hostage token" component runs a PowerShell monitor polling `api.github.com/user` with the stolen GitHub token; if the token is revoked, it executes an attacker-supplied handler via `Invoke-Expression`**, which Socket assesses likely triggers a destructive routine. **To spread, it enumerates packages tied to the victim's publishing identity, builds Sigstore provenance, and republishes them**, and plants **fake Copilot/Dependabot GitHub Actions workflows**. **IOCs: C2 `iseekaigogo[.]com`, resolved via an Ethereum contract; a public GitHub repository titled "Shai-Hulud: Here We Go Again" used as a staging fallback for stolen data; files `package/lib/setup.mjs`, `package/lib/Math_Symbol.js`, `.claude/settings.json`, `.vscode/tasks.json`; dropped binary HackBrowserData; rogue commit `e90c47bbb208e99cac8aa678405b2133f6cb3f52`.** **Action, and the order matters because of the hostage-token trap: first isolate the affected build hosts and developer workstations from the network, then rotate credentials from a clean host, and only then revoke the GitHub tokens — revoking a token while the monitor is still running and able to reach the internet is what fires the destructive handler.** Then **grep every repository you own for `.claude/settings.json` and `.vscode/tasks.json` that you did not author, and for unexpected GitHub Actions workflows named after Copilot or Dependabot**; those are the persistence artefacts, and they are in source control, not on a build agent. Audit **recent publishes under every maintainer identity that touched an affected environment** — the worm republishes through legitimate identities with valid provenance, so Sigstore attestation proves nothing here. Structurally, **`npm config set ignore-scripts true` with an explicit allowlist** is the control that would have stopped this at the `preinstall` hook, and it is the one worth landing this quarter. **Sources:** [The Hacker News](https://thehackernews.com/2026/10/tensorlake-npm-package-compromised-to.html) · [GBHackers](https://gbhackers.com/tensorlake-package-hijacked/)

### 1.3 KEV adds five CVEs from 2015–2023 with an 11 October deadline, because seven governments just published on Flax Typhoon's 1,300-script scanner (NEW)

**Verified programmatically from `cisagov/kev-data` at 06:25 UTC: catalogVersion 2026.10.08, released 2026-10-08T20:09:18Z, 1,739 records — five additions, the first in four days.** All five are old: **CVE-2015-3306** (ProFTPD, improper access control via `site cpfr`/`site cpto`, arbitrary file read and write), **CVE-2015-5477** (ISC BIND, DoS via TKEY queries), **CVE-2016-3081** (Apache Struts command injection via `method:` prefix, **only when Dynamic Method Invocation is enabled**), **CVE-2021-3199** (ONLYOFFICE Docs path traversal via an image-upload parameter, **when JWT is used**, leading to RCE) and **CVE-2023-22894** (Strapi cleartext storage of sensitive information via query filter, **chainable**, and **flagged EoL/EoS with a recommendation to discontinue use**; Strapi's own advisory gives a wider affected range of **3.2.1 through 4.7.9**). **All five carry a 11 October due date, and all five carry the full BOD 26-04 required action including CISA's "Forensics Triage Requirements"** — so for federal agencies this is not a patch-and-close item. The reason they appeared is the same reason they matter to everyone else: **the FBI, CISA, NSA, the UK NCSC and agencies in several other countries published a joint advisory on Chinese state-linked activity consistent with Flax Typhoon / Ethereal Panda / RedJuliett, attributed to Integrity Technology Group**, and these five are among the **eight CVEs** the advisory names as actively exploited — the other three being **CVE-2014-6278** (Shellshock), **CVE-2019-11510** (Pulse Connect Secure) and **CVE-2021-22205** (GitLab). The operation runs **since at least mid-January 2021**, scanning **ports 21, 22, 53, 80, 443 and 1080** with **Nmap, masscan, WPScan and MicroScan** — a Python web application carrying **more than 1,300 penetration-testing scripts, in use since 2017** — paired with a Mirai-class botnet. **Action: this KEV cycle is a perimeter inventory exercise, not a patch cycle.** Nothing here is in your CMDB under a vendor name you recognise; it is a forgotten FTP server, an internal DNS resolver, a document-preview appliance, a headless CMS a marketing team stood up in 2022. **Concretely: scan your own external ranges for those six ports and identify what answers; check whether Struts Dynamic Method Invocation is enabled anywhere (it is off by default and almost never needed); check whether any ONLYOFFICE Document Server instance is internet-reachable; and treat any Strapi 3.x/4.x instance as end-of-life and plan its replacement rather than its patching.** Then do the triage half: for any affected system that was internet-facing, **review web application logs for exploitation attempts, monitor for unexpected Active Directory replication (the advisory names `DC.exe` performing DCSync), and audit cloud accounts for connected applications with file and mail read scopes** — the email-collection tooling is OAuth- and EWS-based, so it leaves no endpoint artefact. **Sources:** [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) · [The Hacker News](https://thehackernews.com/2026/10/fbi-says-china-linked-hackers-ran.html) · [BleepingComputer](https://www.bleepingcomputer.com/news/security/fbi-disrupts-chinese-hacking-tools-used-to-breach-critical-infrastructure/)

### 1.4 Atlassian CVE-2026-21589: 190 exploitation attempts from 32 IPs in 10 countries, and still not in KEV (follow-up, EXPLOITED)

The numbers now exist. **Previdian's honeypot network logged 190 exploitation attempts as of 8 October, from 32 IP addresses across 10 countries** — the first arriving **hours after watchTowr published its analysis on 6 October**, one day after Atlassian's **5 October** disclosure at **CVSS 9.3**. **The individual addresses have not been published**, so there is no blocklist to apply; detection has to be behavioural. Everything else from yesterday stands and is unchanged: the traversal is written as **`..::..::`** to survive a slash-based path filter in **`atlassian-plugins-webresource`** (**6.0.7** vulnerable, **6.0.8** fixed), reads are confined to the Tomcat application context, and the escalation that turns a file read into administrator runs through **`WEB-INF/classes/crowd.properties`**, which carries the **Crowd application password in plaintext** — watchTowr used it to list users through Crowd's REST API, create an account and **add it to `jira-administrators`**, which it described as "basically game over." Crowd IP allowlisting breaks that chain. **Affected: all versions** of Bitbucket, Confluence, Jira Software, Jira Service Management, Bamboo, Crowd, Crucible and Fisheye Data Center. **Fixed:** Bitbucket **9.4.26 / 10.2.8 / 10.5.1**; Confluence **9.2.26 / 10.2.19**; Jira Software **9.12.40 / 10.3.26 / 11.3.12**; Jira Service Management **5.12.40 / 10.3.26 / 11.3.12**; Bamboo **10.2.24 / 12.1.12**; Crowd **6.3.7 / 7.0.3 / 7.1.7 / 7.2.4**; Crucible and Fisheye **4.9.15**. **Verified programmatically this morning: CVE-2026-21589 is absent from KEV**, four days after confirmed exploitation and three after a public PoC — if your change process keys priority off KEV membership, this vulnerability is the argument for changing that process. **Action unchanged and now overdue: patch internet-reachable instances today; if you cannot, cut external access rather than relying on Atlassian's firewall and rewrite rules alone. Then hunt, because exploitation predates most estates' patching: URL-decode access logs up to two passes and search for `..` immediately adjacent to `/`, `\` or `::`, and grep raw log lines for `::` inside `/download/resources/` and `/s/.../_/download/` paths. If `crowd.properties` was readable on any exposed instance, rotate the Crowd application password and audit `jira-administrators` and equivalent groups for accounts created since 6 October.** **Sources:** [SecurityWeek](https://www.securityweek.com/attackers-target-critical-atlassian-vulnerability-within-hours-of-poc-publication/) · [Infosecurity Magazine](https://www.infosecurity-magazine.com/news/critical-vulnerability-atlassian/) · [Security Affairs](https://securityaffairs.com/200591/security/atlassian-vulnerability-comes-under-attack-hours-after-details-go-public.html) · [watchTowr Labs](https://labs.watchtowr.com/you-wont-hear-about-these-even-in-myths-atlassian-jira-confluence-and-more-pre-auth-arbitrary-file-read-cve-2026-21589/)

### 1.5 Public PoCs land for Zammad CVE-2026-102489 and LMCache CVE-2026-105192 — one deadline already expired, one with no patch at all (follow-up, ESCALATION)

Two tracked items moved from "critical but theoretical" to "exploit code is public," and neither has a clean remediation. **Zammad: Horizon3.ai published technical detail and working exploit code on 7 October.** An **unauthenticated** attacker sends a crafted event to the **`/ws` WebSocket endpoint**; the event name resolves to **`Sessions::Event::Base`**, which lacks a **`run()`** method, raising a Ruby **NoMethodError** whose handler returns an object representation rather than a sanitised failure — **leaking connected clients' HTTP Cookie headers and valid `_zammad_session` values**. The chain to RCE: hijack an administrator session, use Zammad's **package-installation feature** to write a malicious **ERB template** over the password-reset email view, trigger a password reset so the mailer renders it, and **ERB executes Ruby as the Zammad OS user**; the PoC then uninstalls the package to clean up. It requires at least one authenticated user connected to the WebSocket service. **DIVD lists 6.3.0 through 6.5.4 as exploitable; 7.0.0 through 7.1.3 contain the flaw but were not exploitable under DIVD's test conditions. CVE-2026-102490 (local privilege escalation from the Zammad user to root) affects 1.5.0 through 7.1.0-alpha and remains unfixed.** Both CVEs were the **initial access vector in the intrusion of DIVD's own systems — first access 21 September, detected the next day**, which DIVD has described as an alleged "agentic AI-powered attack" with the investigation ongoing and no named actor. **The KEV deadline for both CVEs expired on 5 October.** **LMCache: JFrog published a public PoC on 7 October for CVE-2026-105192 (CVSS 9.8), and there is still no fixed release.** The PoC sends a crafted multipart message to a **ZeroMQ DEALER socket on the default port 5555**, carrying a MessagePack extension wrapping a malicious **pickle** object that executes during deserialization — the demo writes the output of `id` to `/tmp/zmq_pwn`, **as root inside the project's official container images** (in-container root, not a host escape). **The vulnerable decoding path appeared in 0.3.9 and persists through 0.5.5, every release candidate to 0.5.6rc3, and the development branch as reviewed on 7 October.** The 9.8 applies only where `--host` is bound to a routable address — but **LMCache's own example Kubernetes deployment binds to all interfaces**. **Action: patch Zammad to a release above 6.5.4 and, because session cookies were leakable, invalidate all active sessions and audit installed Zammad packages and the password-reset ERB template for modifications; review proxy logs for malformed requests to `/ws`. For LMCache, there is nothing to patch — bind the multiprocess server to loopback, audit every Kubernetes manifest derived from the upstream example, and firewall port 5555 to a trusted cluster network only, remembering that any host able to connect can execute code.** **Sources:** [GBHackers — Zammad PoC](https://gbhackers.com/poc-exploit-released-for-zammad-vulnerability/) · [GBHackers — LMCache](https://gbhackers.com/critical-lmcache-rce-vulnerability/)
