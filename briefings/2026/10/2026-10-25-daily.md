## 1. Risk Watch

### 1.1 PHP2Shell — unauthenticated PHP RCE, exploited in the wild (ONGOING)
Two critical PHP flaws, **CVE-2026-109618** (out-of-memory corruption leaves request data partially initialised) and **CVE-2026-109619** (stale global state after free), both **CVSS 4.0 9.2**, allow unauthenticated RCE and worker-memory disclosure (passwords, tokens, API keys). Details leaked publicly on 20 Oct ahead of coordinated disclosure; PHP shipped fixes on 21 Oct: **8.5.12, 8.4.27, 8.3.36, 8.2.35**. watchTowr saw in-the-wild exploitation on 21 Oct; Arctic Wolf reports exploitation attempts and Potassium botnet activity; Cloudflare and AWS have reported large-scale exploit attempts. Palo Alto Networks confirmed PAN-OS and other network products are affected. Older unsupported branches (including PHP 5) are affected and will not be fixed. Not in CISA KEV as of watchTowr's FAQ — re-check.
Action: Inventory PHP runtimes — the CLI `php` version can differ from the PHP-FPM/Apache version, so check the web-facing one. Patch to the fixed versions, apply vendor updates for appliances embedding PHP, rate-limit/WAF-filter in the interim, and hunt for new web shells and unexpected child processes of php-fpm/apache. Rotate secrets on any host that was exposed unpatched since 20 Oct.
Sources: [watchTowr](https://watchtowr.com/intelligence/php-remote-code-execution-php2shell/) · [Unit 42 threat brief](https://unit42.paloaltonetworks.com/cve-2026-109618-cve-2026-109619/) · [Arctic Wolf](https://arcticwolf.com/resources/blog/php2shell-critical-php-vulnerabilities-enable-unauthenticated-remote-code-execution/) · [Qualys](https://blog.qualys.com/vulnerabilities-threat-research/2026/10/20/php-announces-critical-security-release-for-two-vulnerabilities) · [CNN](https://www.cnn.com/2026/10/21/tech/php2shell-vulnerability-ai-intl)

### 1.2 BeyondTrust Remote Support CVE-2026-102764 — China-nexus zero-day (follow-up)
Critical flaw (**CVSS 4.0 9.3**, NVD 3.1 9.8) in an internal messaging component that fails to validate message origin, giving an unauthenticated attacker file operations on the appliance; affects Remote Support up to **26.2.3**. GTIG/Mandiant attribute exploitation to **ARMORY CASTLE** (suspected PRC-nexus, formerly UNC5221; CrowdStrike: Warp Panda), active from **29 Aug** until the patch (8–9 Oct; auto-applied to SaaS). Post-exploitation: privilege escalation to root via SUID, custom backdoors, credential harvesting, lateral movement. In CISA KEV since 16 Oct. One briefing cites 11,000+ exposed appliances (unverified). BeyondTrust is withholding technical details.
Action: Self-hosted customers must confirm the fix is applied (not automatic unless enabled). Because exploitation predates the patch by ~6 weeks, treat patching as insufficient: review appliance for unexpected SUID binaries/new files, rotate credentials the appliance handled, and review sessions/lateral movement from it.
Sources: [BeyondTrust BT26-05](https://beyondtrust.com/blog/entry/bt26-05) · [BleepingComputer](https://bleepingcomputer.com/news/security/beyondtrust-patches-zero-day-exploited-in-attacks-since-august) · [CSO Online](https://www.csoonline.com/article/4236421/beyondtrust-zero-day-tied-to-chinese-spies-puts-remote-support-users-on-alert.html) · [Cybersecurity Dive](https://www.cybersecuritydive.com/news/china-espionage-beyondtrust-zero-day-hacker/833240/)

### 1.3 FortiBleed — credential campaign against FortiGate / GlobalProtect edge devices (ONGOING)
FBI/USSS advisory (6 Oct) describes a global campaign using leaked credentials, infostealer logs, credential stuffing and password spraying, with offline hash cracking; SOCRadar counts **86,644 devices in 194 countries**. Attackers add their own admin accounts and sometimes delete owners', locking organisations out. FBI names **INC/Lynx** and **Payload** ransomware affiliates using this as initial access. Fortinet says it is **not a new vulnerability**. On 23 Oct researchers reported 70,000+ credentials exposed across FortiGate and GlobalProtect with ~38% of victims in APAC. Separately reported (single secondary source, unverified): PeerStitch fileless malware injecting into FortiOS `miglogd`/`iked`, tied to **CVE-2025-61624** — not shown to be related to FortiBleed.
Action: Audit admin accounts and recent config changes on all FortiGate/GlobalProtect devices, reset admin/VPN credentials, enforce MFA, restrict management interfaces to internal/allow-listed sources, and check VPN logs for spray patterns.
Sources: [BleepingComputer](https://www.bleepingcomputer.com/news/security/fbi-ongoing-fortibleed-attacks-lock-out-fortigate-vpn-admins/amp/) · [Infosecurity](https://www.infosecurity-magazine.com/news/fbi-secret-service-fortibleed/) · [FBI IC3 CSA](https://www.ic3.gov/CSA/2026/261006.pdf) · [The Hacker News](https://thehackernews.com/2026/10/hackers-breach-enterprise-firewalls-and.html) · [iThome (PeerStitch)](https://www.ithome.com.tw/news/179767)

### 1.4 Collabora CODE / Nextcloud CVE-2026-110447 — command injection exploited since mid-September
OS command injection in the built-in CODE server app for Nextcloud (**richdocumentscode < 26.4.303**), **CVSS 4.0 9.2**. Exploitation reportedly began mid-September; attackers run commands and plant PHP web shells. Prerequisite: the built-in CODE server must be stopped/not running. Standalone Collabora Online is not affected. One roundup reports CISA added it to KEV on 23 Oct; this could not be confirmed against the official catalog.
Action: Update richdocumentscode to **26.4.303+**, search the Nextcloud web root and app directories for unexpected PHP files, and review web logs for requests to the CODE endpoints since September.
Sources: [BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-exploit-collabora-rce-flaw-to-backdoor-nextcloud-servers/) · [eSecurityPlanet](https://www.esecurityplanet.com/threats/news-collabora-nextcloud-cve-2026-110447/)
