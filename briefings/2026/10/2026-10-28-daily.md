## 1. Risk Watch

### 1.1 PHP2Shell — successful exploitation confirmed, KEV deadline 29 Oct (ONGOING, escalated)
**CVE-2026-109618** (memory corruption) and **CVE-2026-109619** (stale request state), both **CVSS 4.0 9.2**, allow unauthenticated RCE. Fixed versions are **PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35**. CISA added both flaws to KEV on 26 Oct and gave agencies until **Thursday 29 Oct**. New since yesterday:
- **Honeypots:** Perplexity's detection team recorded **35 successful exploits** from two IPs (24 Oct per SecurityWeek), reaching root about 1.6 ms after exploitation, against Apache mod_php on **PHP 8.4.26**. Marcus Hutchins called it the highest-quality confirmation of in-the-wild exploitation so far.
- **Real intrusion:** Unit 42 reports a break-in at a European government entity. Within two hours the attacker had password hashes and MFA secrets, went after the authentication database, set up an NTLM-relay tunnel into Active Directory and attempted Domain Admin escalation. Command batches wrapped in delimiters such as `==SHELLUSER==` / `==PASSWD==` suggest agentic AI tooling after the initial exploit; the exploit itself is not shown to be AI-driven.
- **Memory exposure:** Varonis notes that the bug can expose PHP worker memory (passwords, tokens, API keys).
- **Other activity:** earlier reporting covers Mirai "Potassium" deployment attempts and suspected DPRK scanning (see 27 Oct briefing).

Action: Treat any web-facing PHP that was unpatched after **17 Oct** as potentially compromised. Patch, including EOL branches. Check the php-fpm and mod_php builds, not just the CLI. Rotate secrets that PHP workers held in memory (database creds, API keys, session secrets). Hunt for web shells, children of php-fpm/httpd (`sh`, `curl`, `wget`), outbound tunnels and NTLM relay activity from web tiers. Alert on AD authentication from web servers.

### 1.2 "Tailworm" — Tailscale SSH root escalation, disclosed before a patch (NEW)
On 25 Oct, Erica Windisch (Cyberdione Labs) published 11 findings without coordinated disclosure. The research was tested on **tailscale 1.104.2** and **headscale 0.29.5**. The core issue: an attacker controlling one tailnet device that ACLs allow to SSH to a target can abuse Tailscale SSH Unix-socket forwarding to get **root** on that target, then repeat the step on the next server (worm-like spread). Tailscale confirmed "serious" privilege-escalation issues. Secondary sources report client **1.104.4** (tagged 27 Oct) fixing bulletins **TS-2026-014 to TS-2026-017**: socket forwarding, session memory exhaustion, serve Unix backends reaching the LocalAPI, and an HTTP/2 serve issue. Headscale and part of the app-connector findings remain unfixed. This could not be confirmed on Tailscale's own bulletin page this run.
Action: Upgrade every node running Tailscale SSH or `tailscale serve` to **≥1.104.4** (check with `tailscale version`). Until then, set `TS_SSH_DISABLE_FORWARDING=1` in the tailscaled service, replace tag-wide SSH grants with explicit source→destination pairs, remove unneeded app-connector permissions and serve targets pointing at Unix sockets. On headscale, treat every SSH grant as root on the target. Delete compromised devices at the control plane; reimaging alone does not revoke keys.
Sources: [The Hacker News](https://thehackernews.com/2026/10/unpatched-tailscale-ssh-flaws-could-let.html) · [Cyber Security News](https://cybersecuritynews.com/tailscale-ssh-flaws/) · [HOL (TS-2026-014 / 1.104.4)](https://hol.org/blog/tailscale-tailworm-ssh-root-escalation-ts-2026-014-upgrade-1-104-4) · [Brandefense](https://brandefense.io/security-news/tailworm-tailscale-vulnerabilities-who-is-exposed/)

### 1.3 GMO Internet Onamae Desktop Cloud — extortion escalates, data reportedly published (developing)
GMO detected an intrusion on **20 Oct**. Malicious programs may be on up to **26,739** customer Windows servers, which are mostly used for automated FX trading. All plans have been shut down and Trend Micro is investigating. The attacker demanded **¥8bn (~$50M)**; GMO refused and offered ¥5,000 compensation per customer. The attacker threatened to leak data and launch ransomware at **12:00 JST on 27 Oct**, so GMO told customers to disconnect and shut down their PCs. Customer and company information reportedly appeared online around 12:30 JST. GMO's 13:55 update said no ransomware had been confirmed and the published material was still being verified. Reports that the stolen credentials were used for trades at 70+ brokers, and that the CEO blamed misuse of an AI tool, come from one source each and are unverified. GMO has also asked the Japanese government to use its new active cyber defence powers.
Action: Customers should reset MetaTrader 4/5 and broker credentials, end active sessions, scan any PC that connected to Desktop Cloud, and expect "Hacking Team"-signed phishing. Brokers should watch for anomalous logins from GMO Desktop Cloud IP ranges.
Sources: [BleepingComputer](https://www.bleepingcomputer.com/news/security/japans-gmo-urges-customers-to-shut-down-pcs-amid-ransomware-threat/) · [BleepingComputer (initial breach)](https://bleepingcomputer.com/news/security/japans-onamae-desktop-cloud-hacked-up-to-27-000-servers-affected) · [Investing.com](https://uk.investing.com/news/stock-market-news/japans-gmo-internet-warns-users-of-impending-ransomware-attack-4932902) · [Nippon.com](https://www.nippon.com/en/news/yjj2026102400301/)

### 1.4 HPE ArubaOS — eight maximum-severity RCE / auth bypass flaws (follow-up)
Bulletin **HPESBNW05162** (22 Oct) fixes **72** CVEs in AOS-8 and AOS-10, including **8 rated maximum severity**: unauthenticated, low-complexity RCE and authentication bypass (for example **CVE-2026-79844**, CVSS 10.0 per HPE; the public CVE record currently describes an unrelated product). None is in KEV yet, but edge networking gear with this profile is usually a fast exploitation target, as the Ivanti, PAN-OS and Arista KEV entries this month show.
Action: Patch Mobility Conductors, controllers and gateways to the fixed releases in HPESBNW05162. Keep management interfaces off untrusted networks in the meantime.
Sources: [BleepingComputer](https://bleepingcomputer.com/news/security/hpe-patches-eight-max-severity-rce-and-auth-bypass-aos-flaws) · [Rescana](https://www.rescana.com/post/hpe-aruba-aos-cve-2026-79844-critical-october-2026)

### 1.5 BeyondTrust Remote Support CVE-2026-102764 and FortiBleed (follow-ups)
BeyondTrust (**CVSS 9.3**, exploited by China-nexus **ARMORY CASTLE** since 29 Aug, patch BT26-05-RS on 9 Oct, in KEV) has no new primary-source developments. A single non-primary forecast claims the 26 Oct update says persistence survives version upgrades and that the actor deletes appliance logs; verify against BT26-05 and Mandiant. In the FortiBleed / edge-credential campaign, Group-IB and NyxLab attribute the **70,000+** exposed credentials from FortiGate and GlobalProtect devices to actor **k0t**, linked to **Qilin** and **The Gentlemen** affiliates.

For Fortinet and Palo Alto edge devices, audit admin accounts, reset VPN/admin credentials and enforce MFA.

- **eMudhra CA key compromise:** Microsoft shipped out-of-band Windows updates that distrust certificates chained to eight compromised eMudhra intermediate keys, which came from a weak 2025 key ceremony (six TLS, two code-signing). The updates target machines that don't get automatic trust-list updates, such as air-gapped hosts. Google, Mozilla and Apple have already acted, Oracle (Java) and Python have pushed updates, and eMudhra is leaving the public TLS market. No malicious use of the keys has been shown. Update offline and isolated systems and check for eMudhra-issued certs in your estate.
