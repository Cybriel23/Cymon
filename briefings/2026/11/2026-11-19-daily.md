## 1. Risk Watch

### 1.1 Apache Axis 1.x CVE-2026-90436 exploited via Confluence Data Center and N-able N-central; CISA KEV due 21 Nov (ONGOING)
**CVE-2026-90436** (CVSS **9.8**) is an unsafe-reflection flaw in end-of-life Apache Axis 1.x, **up to and including 1.4**. A SOAP fault with an `exceptionName` element makes Axis load and instantiate a class the attacker chooses. This happens *before* any per-service handler runs, so authentication handlers do not protect against it. The Axis project will ship no 1.x release, so each vendor that bundles Axis must patch its own product. Rapid7 MDR saw exploitation against **Confluence Data Center** on **13 Nov**. It is exposed only when the Remote API (XML-RPC & SOAP) is enabled, and Atlassian lists **9.2.28** as the fixed release. N-able reported same-day in-the-wild attacks on **N-central**, which needs the Legacy API enabled, after a public PoC appeared on 12 Nov. Sources disagree on the date of the 2026.4 HF3 hotfix and whether it fully covers the Axis flaw. CISA added the CVE to KEV on **18 Nov** with a due date of **21 Nov**. Two more entries from the same batch share that deadline: **REDCap CVE-2026-90817** (unauthenticated RCE through survey routing, CVSS 9.8; REDCap has been abused before by China-linked UNC6508 against research institutions) and **Synology DSM/BSM CVE-2024-10441**.
**Action:** Upgrade Confluence DC to 9.2.28 or later, or disable the Remote API now; the change takes effect without a restart, but integrations that use it may break. On N-central, apply the latest hotfix, confirm the Legacy API is off, and hunt with Rapid7's IOCs. Inventory any other Java app that bundles `axis-1.4.jar`. Patch REDCap and Synology by 21 Nov. On REDCap hosts, hunt for shells or interpreters spawned by the web server process.
**Sources:** [Rapid7](https://rapid7.com/blog/post/etr-rapid7-detected-exploitation-of-cve-2026-90436-against-atlassian-confluence-data-center-n-able-n-central-also-exploited), [oss-security](https://openwall.com/lists/oss-security/2026/11/06/12), [CISA KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog), [The Hacker Wire (REDCap)](https://www.thehackerwire.com/redcap-unauthenticated-rce-via-survey-passthrough-and-data-import-cve-2026-90817/)

### 1.2 Java4Shell, OpenJDK HotSpot Base64 RCE (CVE-2026-114938): exploit attempts now observed (follow-up, ONGOING)
This is the HotSpot x86-64 Base64 intrinsic memory-corruption flaw, and it has a precondition: the CPU must support **AVX-512 VBMI**. ARM64 is not affected. Researchers showed pre-auth RCE against default setups of Keycloak, Jira, Confluence, Jenkins, Artifactory and PingFederate. CISA issued an alert on 17 Nov urging immediate patching. Cloudflare's Cloudforce One then reported two things. First, a scanner that sent a Java4Shell exploit attempt about 17 hours after recon, with a Chrome User-Agent. Second, the first traffic tying **ARTEX** (the AI-driven attack framework in the FBI's 13 Nov advisory) and Java4Shell to one IP (**18 Nov 06:59 UTC**). Neither observation proves a successful compromise or a single operator. Fixed OpenJDK builds: **17.0.21.1, 21.0.13.1, 25.0.5.1, 27.0.1.1**, plus Oracle's November patches.
**Action:** Patch internet-facing Java services first. After restarting, confirm the JVM version the *process* actually loads, not just the host's default `java`; bundled and container JDKs are the usual blind spot. Where you can't patch yet, start the JVM with `-XX:-UseBASE64Intrinsics`. Look for repeat requests to the same endpoint and for unexpected JVM crashes or `hs_err_pid*.log` files.
**Sources:** [The Hacker News (CISA alert)](https://thehackernews.com/2026/11/cisa-urges-immediate-patching-of.html), [Cyber Security News (Cloudforce One)](https://cybersecuritynews.com/java4shell-rce-flaw-exploited/), [Help Net Security](https://www.helpnetsecurity.com/2026/11/18/java4shell-openjdk-vulnerability-cve-2026-114938/), [Security Affairs](https://securityaffairs.com/203387/hacking/65-characters-to-rce-inside-the-java4shell-vulnerability.html)

### 1.3 NGINX "nginx2root" HTTP/2 RCE (CVE-2026-123007) and four sibling flaws; public PoC (NEW)
F5/NGINX fixed five flaws, each rated CVSS v4 **9.2** and each needing a particular configuration. **CVE-2026-123007** is the HTTP/2 worker RCE present since **1.9.5 (2015)**. **CVE-2026-123633** affects HTTP/2 proxying when the worker is short of `worker_connections`. **CVE-2026-123634** involves variable-built proxied server names combined with SSI or `mirror` subrequests. **CVE-2026-121810** affects HTTP/3, and **CVE-2026-113425** affects the mail proxy. Fixed versions: OSS **1.31.9 / 1.30.7**, and NGINX Plus **37.3.0.1 / 37.0.8.1**; no fix is listed for Plus R34–R36. Wiz, Xint and Rapid7 all demonstrated code execution. Xint chained it with a Linux SCTP kernel bug to get root, and Rapid7's version took about 128 GB of HTTP/2 traffic. A public PoC is on GitHub. **No in-the-wild exploitation** has been reported yet, and Ubuntu and Debian had not shipped fixed packages at the time of reporting.
**Action:** Upgrade, then do a full restart or binary upgrade, because a reload keeps the old executable running. As an interim fix, disable HTTP/2 (`http2 off;` on 1.25.1+, or remove `http2` from `listen`) and HTTP/3. Block SCTP with `install sctp /bin/false` in `/etc/modprobe.d/`. Test the origin directly with `openssl s_client -alpn h2`. For detection, CIRCL points to workers spawning processes, worker crashes or core dumps, and long HTTP/2 connections with heavy inbound traffic but few logged requests.
**Sources:** [nginx.org advisories](https://nginx.org/en/security_advisories.html), [CIRCL TR-105](https://www.circl.lu/pub/tr-105/), [Wiz](https://www.wiz.io/blog/nginx-http2-rce-vulnerabilities), [Rapid7](https://www.rapid7.com/blog/post/ve-cve-2026-123007-critical-nginx-http-2-integer-underflow-leads-to-rce-fixed/), [The Hacker News](https://thehackernews.com/2026/11/10-year-old-nginx-http2-flaw-lets.html)

### 1.4 Apache Roller CVE-2026-129448 unauthenticated XML-RPC deserialization, actively exploited (NEW)
The ASF says **CVE-2026-129448** (CVSS **9.8**) is "being actively exploited." The XML-RPC endpoint deserializes vendor extension types *before* it authenticates the caller. Affected: **Roller 4.0.0–6.1.4**; fixed in **6.1.6**. The September fix for CVE-2026-82384 listed only 6.1.5 as affected, so older installs that seemed out of scope are exposed. The ASF has given no targeting details and no IOCs.
**Action:** Upgrade to 6.1.6. If you can't, set `enabledForExtensions=false` in `WEB-INF/web.xml`, or remove the `/roller-services/xmlrpc` servlet mapping, then restart. Disabling XML-RPC in the admin UI is **not** enough. Review access logs for POSTs to `/roller-services/xmlrpc`.
**Sources:** [ASF announcement](https://lists.apache.org/thread/lnz4s26tv6hdo03wngtdbpfj4hg4gtds), [The Hacker News](https://thehackernews.com/2026/11/critical-apache-roller-rce-flaw-under.html), [Security Affairs](https://securityaffairs.com/203419/security/apache-roller-rce-flaw-cve-2026-129448-under-active-attack.html)

### 1.5 PHP critical security release today (14:00–14:30 UTC); LiteLLM CVE-2026-40217 in KEV (NEW)
PHP maintainers have announced fixes for **all supported branches**, with "highest severity CRITICAL." They say the critical issues need non-default or uncommon setups. **CVE-2026-115560** is expected among them: session RCE when the serialize handler is `php_binary`/`php_serialize` and then switched to `php` via `ini_set()` before `session_start()`, with session upload progress enabled (the default). The October PHP2Shell flaws (CVE-2026-109618/109619) have seen limited exploitation against Palo Alto and Check Point management interfaces. Separately, CISA added **BerriAI LiteLLM CVE-2026-40217** to KEV, due **2 Dec**. It is RCE through bytecode rewriting at `/guardrails/test_custom_code`, the fourth LiteLLM KEV entry this year.
**Action:** Schedule PHP updates for this afternoon, including the PHP builds bundled in appliances. Until then, set `session.upload_progress.enabled=0` and restart workers. On LiteLLM proxies, upgrade and block or authenticate `/guardrails/*` at the edge.
**Sources:** [php.net announcement](https://www.php.net/archive/2026.php#2026-11-18-1), [The Hacker News](https://thehackernews.com/2026/11/php-warns-of-critical-security-flaws.html), [The Register](https://www.theregister.com/patches/2026/11/18/get-ready-for-another-critical-php-security-release-to-drop/5310911), [CISA KEV catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

## 4. Threat Watch
- **Cold Relic / ColdRiver (FSB-linked): cloud-to-cloud pivoting:** Mandiant/Google describes a late-2025 compromise of a US organization's admin account.
