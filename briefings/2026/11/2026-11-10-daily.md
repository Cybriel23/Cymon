### 1.2 N-able N-central "Able2Shell": 30+ unpatched flaws with public exploits, hosted service offline (NEW, ONGOING)
- **The disclosure:** late on **8 Nov**, researcher Sean Bales published a GitHub repository, "Able2Shell," with proof-of-concept exploits for **30+** N-central flaws. He tested them on pre-release Appliance **2026.4.0.31** and believes earlier versions are affected too. He says the work was AI-assisted.
- **Worst chain:** an unauthenticated XXE in service import is used to steal a trusted local session, reset a password and run commands as the `nable` user. The same chain can create an enabled "Default Administrator" account.
- **Other flaws:** stored XSS that leads to root commands when an administrator views malicious patch metadata, and a privilege escalation from `nable` to root.
- **Why no warning:** Bales says N-able left earlier reports about another product unpatched, so he gave no advance notice this time.
- **N-able's response:** it took hosted N-central offline in the Americas, Europe and APAC on **9 Nov**. It told on-premises customers to take their servers offline and is validating a hotfix. It says it has seen **no exploitation** so far and posts updates every **4 hours**.
- **Why it matters:** this is an RMM platform. Compromising one server gives access to every device that MSP manages, the same pattern as Kaseya VSA in 2021.

**Action:**
- Take on-premises N-central offline as N-able advises, or at least cut it off from the internet.
- Look for new or unexpected administrator accounts (especially "Default Administrator"), recent service-import activity, and unexpected processes running as `nable` or root.
- Prepare to apply the hotfix the moment it is released.
- MSP customers should ask their provider which platform they use.

Sources: [BleepingComputer](https://www.bleepingcomputer.com/news/security/n-able-takes-cloud-platform-offline-after-30-plus-zero-days-published/), [Cyber Security News](https://cybersecuritynews.com/n-able-takes-n-central-servers-offline/)

### 1.3 OpenSSH "SSHole" CVE-2026-123158: in KEV, successful break-ins confirmed (follow-up, ONGOING)
- **KEV listing:** CISA added SSHole on **9 Nov**, with a federal deadline of **12 Nov**.
- **Confirmed break-ins:** GreyNoise recorded the first successful exploitation on **7 Nov at 00:46 UTC**, about 40 hours after the fix. It logged **16** successful exploitation chains from six IP addresses.
- **Attacker activity:**
  - system and container reconnaissance;
  - queries to cloud metadata services;
  - attempts to read password hashes and root SSH keys;
  - writes to `authorized_keys`.
- **Implant:** one actor got root and installed **TAC Agent**, a Python C2 implant with comments in Chinese. Its C2 was `tac.vpnla[.]org`, which it could not reach. The agent has no built-in persistence, so attackers add a startup service.
- **Other telemetry:** Previdian saw **20** attempts from **13** IPs in nine countries. watchTowr linked exploitation to botnets and cryptomining, and Defused saw limited activity.
- **What's affected:** musl-based builds such as Alpine, where password authentication runs without PAM. The fix is in **OpenSSH 10.6p2**.

**Action:**
- Patch now. Otherwise set `PasswordAuthentication no`.
- Hunt for successful password logins to accounts whose `/etc/shadow` hash is `*`, for new SSH keys, and for TAC Agent files or startup services.
- Block `tac.vpnla[.]org`.
- Alpine-based container images need rebuilding, not only the hosts.

Sources: [BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-exploit-sshole-openssh-flaw-to-breach-linux-systems/), [SecurityWeek](https://www.securityweek.com/hackers-exploiting-sshole-authentication-bypass-in-openssh/), [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

### 1.4 KEV batch with a 12 Nov deadline: GPUStack, FreeSWITCH, IBM Aspera Faspex (NEW)
CISA added these three alongside SSHole on **9 Nov**. Federal agencies have three days, which shows how urgent CISA considers them.

- **GPUStack CVE-2026-102895** (Critical):
  - **Flaw:** an auth bypass that trusts loopback requests and forwarded IP headers. It gives unauthenticated admin access, persistent admin API keys and disclosure of worker and cloud-provider secrets. Code can be run through `POST /v2/inference-backends/from-yaml`.
  - **Fix:** fixed in **2.2.0**. Go to **2.2.2**, which also closes CVE-2026-102894.
- **SignalWire FreeSWITCH CVE-2026-116779** (CVSS 9.8):
  - **Flaw:** in an inbound SIP MESSAGE, part of the recipient field is read as a chat protocol name. If it says "api," the input goes to the FreeSWITCH API and runs as server commands. SignalWire reports it is being exploited.
  - **Fix:** fixed in **1.11.3**. Some hardening options ship disabled and have to be turned on after upgrading.
- **IBM Aspera Faspex 5 CVE-2026-123218** (IBM CVSS 9.8):
  - **Flaw:** incorrect authorization that lets a crafted message bypass checks and gain full admin rights.
  - **Affected:** **5.0.0–5.0.19**. The fix is **5.0.19 PL1**; check that the `faspex-core` image is 5.0.19 (1ce4b13, Fix Pack 1). IBM lists no workarounds.

**Action:**
- Inventory self-hosted AI-inference platforms, VoIP switches and file-transfer appliances.
- Patch within the KEV window.
- **GPUStack:** treat any instance exposed to the internet as compromised and rotate cloud credentials.
- **FreeSWITCH:** review SIP MESSAGE logs for `api` recipients.
- **Faspex:** audit for new admin users.

Sources: [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog), [IBM bulletin](https://www.ibm.com/support/pages/node/7295921), [SecurityOnline (FreeSWITCH)](https://securityonline.info/freeswitch-vulnerability-cve-2026-116779-exploited/), [SecurityOnline (GPUStack)](https://securityonline.info/gpustack-authentication-bypass-cve-2026-102895-exploited/)

### 1.5 Refrigeration-controller sabotage attributed to the IRGC; US joint advisory (follow-up, ONGOING)
- **Attribution:** on **9 Nov**, France's Cyber Crisis Coordination Centre (ANSSI, cyber command, DGSE, DGSI) attributed the October attacks to **Shahid Kaveh**, an IRGC cyber unit previously tied to attacks on US water-utility PLCs.
- **The October wave:** about **700** French grocery sites were hit. France reports extensive food losses and at least **15 fires**. The same actors also targeted Schneider Electric equipment at small hydroelectric plants, with moderate disruption.
- **France's response:** it summoned Iran's ambassador and is seeking EU sanctions. The Paris prosecutor has opened a judicial investigation and requested international arrest warrants for the unit's head and two deputies.
- **Not yet attributed:** the early-November second wave (11+ countries, including three French blood-service sites).
- **US advisory:** CISA, FBI, HHS, USDA and DOT warned that attackers force cold-chain controllers into continuous heating and defrost cycles. They are exploiting authentication bypasses, code injection and default credentials.
- **Separate abuse:** SecurityScorecard found exposed Copeland XWEB controllers being turned into spam and proxy infrastructure.

**Action:**
- Take refrigeration and BMS controllers off the internet, change default passwords, and put remote access behind a VPN with MFA.
- Alert on setpoint and defrost-schedule changes.
- Make sure temperature alarms reach staff out of hours.

Sources: [The Record](https://therecord.media/france-blames-iran-for-fridge-cyberattacks), [The Hacker News](https://thehackernews.com/2026/11/us-agencies-warn-refrigeration.html), [Help Net Security](https://www.helpnetsecurity.com/2026/11/09/copeland-xweb-refrigeration-controllers-spam-botnet/), [BleepingComputer](https://www.bleepingcomputer.com/news/security/france-blames-iranian-hackers-for-supermarket-attacks-that-sparked-fires/)
