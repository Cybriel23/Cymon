## 1. Risk Watch

### 1.1 VMware vCenter CVE-2026-123890 zero-day exploited by ARMORY CASTLE since September (NEW, ONGOING)
**CVE-2026-123890** (CVSS **9.8**) is an unauthenticated SRP-6a session-key disclosure in the VMware Directory Service (`vmdird`, DCE/RPC on **port 2012**). It yields an authenticated `administrator@vsphere.local` session on vCenter **7.x and 8.x**. It is fixed in **vCenter 9.1.1.0200, 9.0.2.0200 and 8.0 U3m** (Broadcom advisory 39495, which also ships in VCF). **vCenter 7.0 is out of support and gets no patch.** Mandiant/GTIG attribute exploitation to **ARMORY CASTLE** (formerly **UNC5221**, also called Warp Panda), a suspected PRC espionage group. The chain started with the **BeyondTrust Remote Support zero-day CVE-2026-102764**, moved to internal Linux appliances without EDR, and then used **BONESAW** against vCenter. BONESAW stole the vmdir LMDB, extracted the STS SAML signing key and created a rogue SSO admin. **SAWSNAKE** then forged SAML tokens (Golden SAML, which bypasses MFA). The actor enabled SSH through the VAMI API, stole the vCenter master key and PostgreSQL credentials, then pivoted to ESXi to pull NTDS.dit and registry hives from guest disks. The playbook matches earlier BRICKSTORM-era vSphere intrusions. Patches against the July bypass **CVE-2026-59309** did not stop it.
**Action:** Patch now; isolate or replace vCenter 7.0. Restrict 2012/443/5480/22 to admin networks, and patch BeyondTrust RS (BT26-05). Hunt for VAMI `PUT /rest/appliance/access/ssh`, new SSO or local admins (e.g. `sps-*@vsphere.local`), `/tmp/123`, `/tmp/sss`, `/tmp/dbr`, `/usr/bin/vmtoolscs`, `ActiveSer.jsp`/`u.jsp` webshells, SUID on `/bin/env`, the `SSH-2.0-pulsesecure_23345` banner, a hidden `.a` directory or `o.tar.gz` on VMFS, and outbound Slack API traffic from appliances. If you find anything, rotate the STS signing certificate, the vCenter master key, the `vpxuser` and PostgreSQL credentials and ESXi root keys. Mandiant's report lists IPs and YARA rule names.
**Sources:** [Google Cloud / Mandiant](https://cloud.google.com/blog/topics/threat-intelligence/armory-castle-exploits-vsphere), [SecurityWeek](https://www.securityweek.com/newly-patched-vmware-vcenter-flaw-exploited-as-zero-day-by-chinese-apt/), [BleepingComputer](https://www.bleepingcomputer.com/news/security/vmware-patches-vcenter-zero-day-exploited-in-attacks-since-september/), [The Hacker News](https://thehackernews.com/2026/11/critical-vmware-vcenter-flaw-cvss-98.html)

### 1.2 PHP security release: 18 CVEs incl. phpAfterShell (CVE-2026-126714) and PHP-FPM smuggling RCE (follow-up)
PHP shipped **8.5.13, 8.4.28, 8.3.37 and 8.2.36** (and PHP **8.6.0**, which includes the fixes). **CVE-2026-129289** (CVSS **9.2**) is unauthenticated PHP-FPM request smuggling that leads to code execution, but only where the web tier **reuses backend connections** to FPM (some nginx, Apache, HAProxy and LSAPI setups). **CVE-2026-126714 "phpAfterShell"** (Depthfirst, CVSS 4.0 **9.2**) lets an interrupted file-session write make PHP load an attacker-chosen object. RCE needs a gadget chain or a second bug, and the full chain is withheld. The October PHP2Shell fixes did not cover it. Also fixed: **CVE-2026-115560** (session serializer mismatch), two UAF→RCE bugs (**CVE-2026-129474**, **CVE-2026-129496**), an FPM epoll UAF LPE (**CVE-2026-129291**) and a PHAR signature downgrade (**CVE-2026-128090**). No in-the-wild exploitation is reported. The updates turn upload progress **off by default**.
**Action:** Upgrade and rebuild images. Distro packages may carry the fix without a version bump, so verify the version the *web-serving* PHP reports. Interim: `session.upload_progress.enabled=0`, disable persistent connections to PHP-FPM, and never expose FPM or LSAPI listeners. For EOL PHP, use the Ondřej Surý or vendor backports.
**Sources:** [BleepingComputer](https://www.bleepingcomputer.com/news/security/php-security-updates-fix-18-flaws-including-critical-rce-bugs/), [The Hacker News (phpAfterShell)](https://thehackernews.com/2026/11/phpaftershell-explained-how-hackers.html), [The Hacker News](https://thehackernews.com/2026/11/php-fixes-7-critical-flaws-including.html), [SecurityWeek](https://www.securityweek.com/php-patches-seven-critical-rce-vulnerabilities/)

### 1.3 Java4Shell (CVE-2026-114938): probing grows, vendor exposure list widens (follow-up, ONGOING)
GreyNoise counted **150+** Java4Shell-shaped requests from five IPs by early 19 Nov. Previdian saw **nine** attempts from six IPs on 18–19 Nov. watchTowr describes the blind attempts as "not yet functional," and no successful intrusion is confirmed. Cloudflare saw one IP doing both **ARTEX** and Java4Shell activity, and scanners switching to Chrome User-Agents. Working RCE exploits now exist privately (VulnCheck for customers, and Immersive's Kevin Breen). Vendor status: **Cisco** lists more than a dozen affected products (Catalyst Center, Secure Network Analytics, Secure Workload, SSM On-Prem, Intersight VA and others) with **no fixes yet**. **Elastic**: Elasticsearch ≥ **7.17.3** is affected, with RCE needing read credentials. **Siemens** advises taking three Industrial Edge Management products offline. **Red Hat** (RHSB-2026-018) rates it Critical for RHEL 8–10. **Keycloak** images are fixed in **26.8.2-3**. **Atlassian** Data Center: disable AVX-512 until patches ship. Amazon, Microsoft and Azul have patched builds. Still not in KEV.
**Action:** Patch exposed JVMs, then confirm the running process's JDK. For vendor appliances without a fix, restrict exposure or use `-XX:-UseBASE64Intrinsics` or AVX-512 disablement where the vendor supports it. Alert on `java4shell-recon` User-Agents and JVM crash dumps (`hs_err_pid*.log`).
**Sources:** [SecurityWeek](https://www.securityweek.com/java4shell-exploitation-attempts-begin-as-vendors-rush-out-advisories/), [Qualys](https://blog.qualys.com/vulnerabilities-threat-research/2026/11/17/how-to-find-mitigate-and-patch-the-critical-java4shell-flaw-cve-2026-114938-now), [Sonatype](https://www.sonatype.com/blog/critical-openjdk-rce-cve-2026-114938-what-to-know)

### 1.4 Cisco Expressway CVE-2026-76466 exploited shortly after public PoC (NEW)
**CVE-2026-76466** (CVSS **9.8**, disclosed by Cisco on 21 Oct) affects **clustered** Expressway Core/Edge. Holding persistent cookies lets an unauthenticated attacker reach the database service, issue RPC commands and run code as **root**. It is fixed in **X15.5.20**; X14 and earlier must migrate. Russian firm **F6** saw attackers breach two internet-facing **X15.5.3** nodes at a Russian organization, pivot to internal cluster nodes, and stage Python tooling against SMB, SQL Server, WinRM and GitLab. The scripts had comments suggesting an AI assistant wrote them. The attacks came soon after a GitHub PoC. Cisco's advisory still says it knows of no malicious use, and the activity is unattributed.
**Action:** Upgrade to X15.5.20. Until then, block TCP **4371–4372** except between trusted cluster nodes. Review the Expressway Erlang system logs for unexpected RPC activity, and treat compromised clusters as a credential-theft event.
**Sources:** [SecurityWeek](https://www.securityweek.com/hackers-exploit-cisco-expressway-vulnerability-soon-after-poc-release/)

### 1.5 Drupal core installer flaw CVE-2026-132165 (SA-CORE-2026-017); exploits expected quickly (NEW)
**CVE-2026-132165** (Drupal risk **18/25**, Critical) lets an unauthenticated attacker use `/core/install.php` to attempt a reinstall, leading to site takeover or RCE. It is fixed in **11.4.13, 11.3.22 and 10.6.22**. Drupal **11.2.x and earlier, 10.5.x and earlier, and 8/9 are EOL with no fix**. The installer stays on every site, and core's default `.htaccess` does not block it. Some paths fail where `settings.php` is not writable. Drupal describes the vulnerable setups as uncommon, but a PoC exists and the security team warned that exploits could appear "within hours or days." No attacks are reported yet.
**Action:** Update, then block `/core/install.php` at the web server or `.htaccess` (or remove it via Composer scripts) even after patching. Make `settings.php` read-only. Check logs for requests to `install.php`.
**Sources:** [The Hacker News](https://thehackernews.com/2026/11/drupal-patches-critical-installer-flaw.html), [BleepingComputer](https://www.bleepingcomputer.com/news/security/drupal-patches-critical-rce-flaw-warns-exploits-may-surface-quickly/)
