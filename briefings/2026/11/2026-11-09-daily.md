The weekend was quiet: no new KEV additions since Friday and no new zero-days. ## 1. Risk Watch

### 1.1 SonicWall SonicOS SSL-VPN SAML/MFA bypass CVE-2026-19868 (follow-up, ONGOING)
- **Status:** the CVE has been in CISA KEV since **6 Nov**, and federal agencies must patch by **20 Nov**. SonicWall still describes only "potential exploitation." No details of the attackers or their methods have been released.
- **The flaw:** a user with valid credentials for another authentication method can get past SAML login, including SAML-enforced MFA.
- **Affected:** Gen7 **7.3.3-7015** and earlier, and Gen8 **8.2.2-8015** and earlier, but only where SSL-VPN uses SAML login.
- **Fixed in the same release:**
  - two **CVSS 8.8** management-interface flaws (**CVE-2026-107155**, **CVE-2026-107154**);
  - a pre-authentication SSL-VPN overflow (**CVE-2026-82308**).
- **No fix coming:** two flaws in end-of-life GMS (**CVE-2026-109593/-109594**) will not be patched. SonicWall advises migrating to Network Security Manager.

**Action:**
- Upgrade to **7.3.4-7013** or **8.2.3-8015**. Until then, consider disabling SAML-based SSL-VPN login.
- Review SSL-VPN logs since October for sessions with no SAML/MFA step.
- Restrict the management interface to trusted networks.
- Plan to move off GMS.

Sources: [The Hacker News](https://thehackernews.com/2026/11/cisa-flags-sonicwall-sonicos-mfa-bypass.html), [Cyber Security News](https://cybersecuritynews.com/sonicos-sslvpn-vulnerability-exploited/), [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

### 1.2 OpenSSH "SSHole" CVE-2026-123158: SANS ISC confirms targeted attempts (follow-up, ONGOING)
- **New evidence:** Johannes Ullrich's Cowrie honeypots at SANS ISC logged the first clear exploit attempts on **5 Nov**. These were passwords made entirely of repeated "A" characters: **232** long-password requests that day, then **713** on **6 Nov**.
- **Earlier traffic:** long passwords seen from **1 Nov** looked like broken brute-force scripts, not deliberate SSHole attempts.
- **Most active sources:** **213.86.169.133**, **152.233.50.185** and **92.255.57.7**.
- **How to read it:** these are attempts. Ullrich suspects some logins succeeded but has not confirmed it. This is the second independent signal after Friday's single-vendor report of root access on an Alpine honeypot. The flaw is still not in KEV.
- **The bug:** on musl builds checking passwords without PAM, a **257–1,024-byte** password makes `crypt()` return `*`. That matches the `*` hash of locked accounts, so the login succeeds. Exploitation also needs at least one other local account with a valid SHA-crypt hash.
- **Fixed in:** **OpenSSH 10.6p2**; Alpine packages are out.

**Action:**
- Patch and restart `sshd`. Where you can't, set `PasswordAuthentication no`.
- Distros may backport the fix, so check package revisions rather than version banners.
- Hunt for successful password logins to key-only or system accounts, especially a failure followed by acceptance in the same session.
- Block the three IPs above.

Sources: [Cyber Security News (SANS ISC data)](https://cybersecuritynews.com/openssh-sshole-flaw-exploited/), [Help Net Security](https://www.helpnetsecurity.com/2026/11/06/openssh-sshole-cve-2026-123158-exploitation/), [The Hacker News](https://thehackernews.com/2026/11/hackers-exploited-openssh-sshole-flaw.html)

### 1.3 React Server Components RCE GHSA-xqc2-xf4c-x3h3, CVSS 9.5 (NEW to this briefing)
- **The advisory:** React published it on **14 Oct** and it drew wide coverage on 9 Nov. Specially crafted payloads can trigger unauthenticated remote code execution in frameworks that support RSC.
- **Narrow trigger:** it requires a response carrying several typed arrays alongside an attacker-controlled value. React calls this "extremely rare" and, consistent with that, the CVSS vector marks additional attack requirements as present.
- **Affected packages:** `react-server-dom-webpack`, `-parcel` and `-turbopack`, versions **19.0.0–19.0.8**, **19.1.0–19.1.9**, **19.2.0–19.2.8** and **19.3.0**.
- **Fixed versions:** **19.0.9 / 19.1.10 / 19.2.9 / 19.3.1**.
- **Identifiers:** no CVE has been assigned. This is not React2Shell (CVE-2025-55182), and the fixed versions from that flaw are still inside the vulnerable ranges here.
- **Exploitation:** none reported.
- **Reliability:** we could not retrieve the primary GitHub advisory, so the version ranges come from two outlets that quote it.

**Action:**
- Check the resolved `react-server-dom-*` versions in lockfiles and in deployed builds, including those bundled by Next.js.
- Upgrade, rebuild and redeploy.
- Client-only React apps are not affected.
- Verify the version ranges against React's GitHub advisory.

Sources: [Cyber Security News](https://cybersecuritynews.com/react-server-components-vulnerability-patch/), [GBHackers](https://gbhackers.com/critical-react-server-components-vulnerability/)

### 1.4 WordPress core upgrade-window RCE CVE-2026-119977 (follow-up, ONGOING)
- **Status:** nothing new since Saturday. Wordfence's count of blocked attempts is still above **240,000** since 28 Oct.
- **What's at risk:** sites below **7.1.4** remain exposed whenever a full-package core upgrade runs. The update to 7.1.4 itself runs the old updater code one last time.

**Action:**
- Confirm sites are on **7.1.4+**.
- Search access logs for external requests to PHP files under `/wp-content/upgrade/`.
- Audit for new administrator accounts and PHP files created during upgrade windows.

Sources: [GBHackers (Wordfence telemetry)](https://gbhackers.com/exploit-wordpress-core-over-240000-attack/), [The Hacker News](https://thehackernews.com/2026/11/installing-fix-for-exploited-wordpress.html)

## 3. Incident Watch
- **Iris Ohyama / Iris Plaza, Japan (new):**
  - **What happened:** attackers got into a third-party cloud service used by the household-goods maker's online store. The provider has not been named.
  - **Who is affected:** up to **7.7M** people, about **5.8M** current and former members and **1.9M** non-members. The final count is still being determined.
  - **Data:** names, addresses, phone numbers, email addresses, gender, dates of birth and (encrypted) member passwords. No card data.
  - **Timeline:** detected late October, sites suspended **28 Oct**, regulators and police notified, update issued **5 Nov**.
  - **Status:** no misuse confirmed, no ransom demand disclosed, no group has claimed it.
  - **Risk:** expect impersonation phishing in Japanese, plus credential stuffing against anyone who reused their Iris Plaza password.
  - [BleepingComputer](https://www.bleepingcomputer.com/news/security/iris-ohyama-data-cloud-breach-exposes-info-of-77-million-customers/)
- **Brenner Base Tunnel SE, Austria/Italy (new):**
  - **Confirmed:** on **7 Nov**, the company building the Brenner rail tunnel told ANSA that unauthorized parties accessed some of its data. It says the affected systems are isolated, operations are unaffected, and forensic experts and the authorities are involved.
  - **Claimed:** the Everest extortion group says it took **812 GB** (listing dated **17 Oct**). This is not verified, and Everest is known to exaggerate data volumes.
  - **Not shown:** there is no evidence of access to operational or industrial systems, or of encryption.
  - **Risk:** engineering documents could help reconnaissance, and fraudsters could pose as the project to its contractors.

## 4. Threat Watch
- **NVIDIA board orders an independent review of foreign-intelligence targeting of CEO Jensen Huang (developing):**
  - **Single-source report:** GBHackers says that on **8 Nov** a committee of independent directors, with outside counsel, began reviewing reports that a foreign intelligence service targeted Huang. According to the same report, the board says it has no evidence that national-security information or company secrets were compromised. We could not find the statement on NVIDIA's newsroom.
  - **Background:** this follows New York Times reporting that US officials suspected businesswoman Alice Huang (ex-Megaspeed) of being a Chinese intelligence asset. China denies it.
  - **Next step:** House committee chairs have asked Huang to brief them in closed session on **18 Nov**.
  - **What it isn't:** nothing indicates a technical intrusion. Treat it as an insider and executive-protection issue.
  - [GBHackers](https://gbhackers.com/nvidia-investigates-suspected-foreign-espionage-campaign/), [Axios](https://axios.com/2026/11/05/jensen-huang-nvidia-congress-china)
- **Infostealer credentials used within ~8 minutes (Elastic):** across **27** confirmed infostealer cases, attackers logged in with stolen credentials an average of **eight minutes** after infection.
  - **Entry point:** ClickFix-style fake verification pages were the most common way in (**12** cases).
  - **AI tools misused after access:** Elastic also documents intrusions where attackers, once inside, used Claude Code (through its VS Code extension, on Windows) and the ChatGPT desktop app (on macOS) to run commands. In the macOS case that meant reading an internal document and the user's password store. Neither case involved a flaw in the AI tool.
  - **Lesson:** session-token revocation has to happen within minutes, not hours.
  - [Help Net Security](https://www.helpnetsecurity.com/2026/11/09/elastic-businesses-remote-access-attacks-report/)
- **ArmorSteal (Python infostealer, clipboard hijacker and miner):** Seqrite analysed a newer build of the family Zscaler documented on 22 Oct.
  - **Delivery:** typosquatted Chocolatey and Microsoft Activation Scripts pages serve a PowerShell one-liner.
  - **Install location:** `C:\Windows\SystemHealth\Update`, with a bundled Python 3.11 runtime and PyArmor 9.1.7 (trial) obfuscation.
  - **Persistence:** scheduled tasks **SysCheck2**, **SysCheckX** and **SysHeal**.
  - **Tricks:** it adds Defender exclusions for `C:\Windows` and `xmrig.exe`, exits on Google, Amazon or Microsoft network ranges, rotates through 11 C2 domains (including `datamons[.]org`), and kills its miner whenever Task Manager or Process Explorer opens.
  - **Hunt:** look for those task names, check whether Defender's exclusion list has changed, and alert on PowerShell run from fake tool-install pages.
  - [GBHackers](https://gbhackers.com/armorsteal-malware-attack/)
- **Dark Project ransomware-as-a-service:** active since **June 2026**, it is recruiting affiliates over Tox with an **80/20** revenue split. Its leak-site records list **38** victims in eight countries (**30** in the US), mainly manufacturing, healthcare and construction. Those listings are claims, not verified compromises. [Cyber Security News (Gurucul)](https://cybersecuritynews.com/new-dark-project-ransomware-group/)
- **NotC2, AWS-native AI command-and-control (research proof of concept):**
  - **The design:** Varonis built a C2 channel entirely from AWS services. SQS carries commands in, Lambda executes them, SNS sends results out over HTTPS, and Bedrock turns plain-language instructions into AWS API calls.
  - **The limit:** it requires credentials the attacker already stole and grants nothing beyond them. But it blends into normal cloud traffic.
  - **Defence:** enforce least-privilege IAM, and alert on new SNS HTTPS subscriptions to outside endpoints and on unusual Lambda-to-Bedrock activity.
  - [Varonis](https://www.varonis.com/blog/notc2-ai-powered-c2-channel), [GBHackers](https://gbhackers.com/notc2-ai-powered-hacking/)
- **European refrigeration-controller attacks (follow-up):**
  - **Timeline:** the first wave hit about **700** French supermarkets on **11–12 Oct**. A second wave on **1–2 Nov** reached **100–115** sites in at least 10 more countries.
  - **New detail:** Unit42's write-up adds per-country exposure data and confirms French reports that medical-facility refrigeration was also affected.
  - **Still unknown:** the actor is unidentified.
  - **Action:** take refrigeration controllers off the internet.
  - [Unit42](https://unit42.paloaltonetworks.com/europes-refrigeration-systems-attacks/)
