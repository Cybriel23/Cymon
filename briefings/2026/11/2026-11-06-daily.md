## 1. Risk Watch

### 1.1 OpenSSH "sshole" CVE-2026-123158: password bypass on musl/Alpine without PAM (NEW)
**The flaw (disclosed 5 Nov, researcher Özgün Kültekin):** musl's `crypt()` returns `*` when given a `$5$`/`$6$` password longer than 256 bytes. OpenSSH then compares that `*` with the `*` stored for accounts that have no password, and the two match.
- **Impact:** an attacker who knows the name of a passwordless account and sends a password of **257–1,024 bytes** logs in on the first try. The bug dates back to OpenSSH's 2016 timing fix for CVE-2016-6210.
- **Severity:** OpenSSH calls it critical; Synology lists **CVSS 8.1**.
- **Exposed only if all of these apply:**
  - sshd is built without PAM, or uses `UsePAM no`. This is the default for Alpine's `openssh-server`.
  - `PasswordAuthentication yes`, which is OpenSSH's default.
  - At least one account has `*` in its password field.
  - Another local account has a `$5$`/`$6$` hash.
- **Alpine cloud images:** official tiny-cloud images **3.18.11–3.24.3** ship an `alpine` user with `*` and passwordless `doas`, so they become root-exploitable as soon as any `$6$` hash exists.
- **Not affected:** glibc distributions (Debian, Ubuntu, Fedora), PAM-based password checks, and Dropbear.
- **Fixes:** OpenSSH **10.6p2**. Alpine edge **10.6_p2-r0**, 3.24 **10.3_p1-r2**, 3.23 **10.2_p1-r1**, 3.22 **10.0_p1-r11**, 3.21 **9.9_p2-r1**, with backports down to 3.16 (**9.0_p1-r6**).
- **Exploitation:** none reported yet. The method is now public and trivial to use.

Action:
- Run `apk upgrade -U -a`, then `rc-service sshd restart`. The upgrade does not restart the running daemon.
- Or set `PasswordAuthentication no`, check it with `sshd -T`, then restart.
- Check whether anything was abused: look in `/etc/shadow` for `*` accounts, and in `/var/log/messages` for "Accepted password for" on those accounts. Review `doas` use and `authorized_keys`.
- Also check Buildroot, Yocto and OpenWrt images that use OpenSSH rather than Dropbear, and musl-based containers that run sshd.

Sources: [Alpine advisory](https://alpinelinux.org/posts/2026-11-05-openssh-password-authentication-bypass/) · [OpenSSH 10.6p2 release notes](https://www.openssh.org/releasenotes.html#10.6p2) · [sshhole.com](https://sshhole.com/) · [Synology-SA-26:16](https://www.synology.com/security/advisory/Synology_SA_26_16) · [The Hacker News](https://thehackernews.com/2026/11/openssh-issues-emergency-fix-for-flaw.html)

### 1.3 US agencies urge hardening of refrigeration and cold-chain controllers (follow-up, DEVELOPING)
**The fact sheet (5 Nov):** CISA, FBI, HHS, USDA and DoT warn about attacks on electronic temperature and commercial refrigeration controllers. Attackers use authentication bypass, code injection and weak settings on unpatched or internet-reachable controllers to force units into continuous heating and defrost cycles. The results are stock losses, fire risk and loss of temperature visibility.
- **Sectors:** food, healthcare, chemical and transportation.
- **What it leaves out:** it names no vendors, protocols or actors.

**Context:**
- **Europe:** hundreds of supermarkets across the October and 2 Nov waves.
- **France:** cold rooms at three EFS plasma sites, reached through the provider Coolworld, which blames an unnamed third-party component.
- **US:** defrost and heating events at about **six** military commissaries since late August (Defense One). The Record reports a DoD inspector-general investigation. Defense One also reports, via Nextgov/FCW, that US officials suspect Iran-linked hackers; this is a suspicion, not a confirmed attribution.
- **Exposure (Censys, 9 Oct–5 Nov):** controllers reachable from the internet fell **53%**, from **6,695** to **3,124** hosts.
  - **Danfoss StoreView:** **708** left, mostly in France and Belgium (CERTFR-2026-ALE-012; CVE-2025-41450/41451/41452).
  - **Copeland/Dixell XWEB:** **2,420** left, led by Italy and Greece.
  - Each attack wave was followed by a drop in exposure.

Links between these clusters are unproven, and no group has claimed any of them.

Action:
- Check your public IP space for Danfoss StoreView and Copeland/Dixell XWEB interfaces and take controller panels off the internet. Put any remote access behind an up-to-date VPN or firewall with allow-listing and MFA.
- Move refrigeration OT onto its own VLAN and change default passwords.
- Set setpoint limits and alert when they are changed.
- Keep temperature alarms that work independently of the remote platform.
- Ask refrigeration contractors and equipment rental firms which remote-monitoring software they use.

Sources: [CISA fact sheet](https://www.cisa.gov/resources-tools/resources/us-government-partners-urge-hardening-industrial-refrigeration-and-cold-chain-monitoring-systems) · [The Record](https://therecord.media/cyberattacks-refrigeration-cisa-fbi) · [Defense One](https://www.defenseone.com/threats/2026/11/warn-refrigerator-hacks-attacks-military/417076/) · [Censys](https://censys.com/blog/european-refrigeration-controller-exposure-sitrep/) · [SecurityWeek (EFS)](https://www.securityweek.com/cyberattack-hits-french-blood-bank-site-but-no-blood-products-are-compromised/)

### 1.4 CWPdoor: trojanized Control Web Panel web server with log-free command execution (NEW)
**The backdoor (QiAnXin XLab):** a fake updater, `cwpsrv_update.sh`, replaces the **cwpsrv 1.15.10** or **1.24.0** binary with a rebuilt one that behaves normally until it gets a signed, encrypted command in `X-Ngx-Integrity-*` headers.
- **Stealth:** those requests are removed from the access logs, and the original file timestamps are restored. It had **0/63** detections on VirusTotal.
- **Prerequisite:** installing it needs root, so the server is already compromised by then.
- **Timeline and links:** XLab caught the installer on **29 Jun**. An archive uploaded from Brazil also held **Ebury**; the link between the two is unclear.
- **Exposure:** XLab counts more than **340,000** CWP instances on the internet.

Action:
- On CWP hosts, run `ss -axp | grep integrity` to look for the `ngx_http_integrity_helper` socket, and `strings /usr/local/cwpsrv/bin/cwpsrv | grep X-Ngx-Integrity`. Also look for unexpected cwpsrv helper processes.
- **IOCs:** 136.0.141[.]71; installer MD5 `e505d4ffa21cf494a5dc2d7c8f4f1236`; backdoored binary MD5s `965aea67fb40de1bab5169ada993349f` (1.15.10) and `d3f4e95113d49ab3991b45e457bda75b` (1.24.0).
- If anything matches, rebuild the server, check it for Ebury, and rotate all panel and SSH credentials.

Sources: [XLab](https://blog.xlab.qianxin.com/cwpdoor-the-invisible-backdoor-living-inside-control-web-panel/) · [The Hacker News](https://thehackernews.com/2026/11/hackers-hide-linux-backdoor-in-control.html) · [BleepingComputer](https://www.bleepingcomputer.com/news/security/hackers-backdoor-linux-servers-using-trojanized-cwp-web-server/)

### 1.5 Apache OFBiz 24.09.08 fixes 46 CVEs, including several pre-authentication RCEs (NEW)
**The release (4 Nov):** all earlier versions are affected. The Apache advisory says some issues are critical but does not score them individually. OFBiz has a history of quick exploitation and KEV listings.

**The most serious fixes:**
- **Pre-authentication RCE:** **CVE-2026-68524** (attacker-controlled screen definitions), **CVE-2026-83542** (login-page widget injection), and CVE-2026-73578 (authorization bypass leading to RCE).
- **Authentication and admin access:** **CVE-2026-105330** (hard-coded JWT key gives admin access), **CVE-2026-109928** (password-reset account takeover), and **CVE-2026-92887** (REST API authentication off by default).

**Exploitation:** none reported yet.

Action:
- Upgrade internet-facing OFBiz to **24.09.08** now. If you cannot, restrict access to `/webtools`, the REST API and the login pages.
- Rotate JWT signing keys and admin passwords after upgrading.
- Review web logs for unusual screen or widget parameters.
