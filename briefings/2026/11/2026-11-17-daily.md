Tuesday, 17 November 2026 · Coverage: 06:00 UTC Mon 16 Nov – 06:00 UTC Tue 17 Nov 2026 and follow-ups on tracked topics

## Executive Summary
The tempo is high, driven by one large web supply-chain compromise and a cluster of reports on AI-agent offensive tooling. Four items need attention today. **First**, an attacker abused a flaw in Optimizely's Experimentation signup flow to inject a skimmer, crypto-wallet swapper and iOS exploit-kit loader into **188** customer script files belonging to **178** organisations, including CNN, BBC, Zoom, Salesforce, KLM and Air France. If your sites load Optimizely, check what they served on **16 Nov**. **Second**, N-able has shipped the follow-up fix for the exploited N-central chains: **2026.4 Hotfix 3** fixes **17** CVEs, and Agents and Probes must be upgraded too. **Third**, Huntress shows that ScreenConnect **CVE-2026-84869** (CVSS **9.9**) is being sprayed at MSP servers to compromise *technician* workstations. Patching the server alone does not help: every host client must be on **26.6.5+**. **Fourth**, Google GTIG and Amazon published primary reports on AI agents that build exploits from patches and hunt for exposed AI gateways (LiteLLM, Langflow, RAGFlow, Dify) to steal model keys. Separately, Microsoft has removed eMudhra roots from Windows, and eMudhra G1 issuance stops today. Watch this week for: Optimizely's root-cause report and customer notifications, the final Microsoft 365 post-incident report, distro kernel updates for NoisyTCP, Apple's **30 Nov** eMudhra distrust, and any Danfoss AK-SM800A fix.

## 1. Risk Watch

### 1.1 Optimizely Experimentation supply-chain compromise: skimmer, wallet swapper and iOS exploit loader on 178 brands' sites (NEW)
On **16 Nov**, an attacker "exploited a vulnerability in the Experimentation account signup flow" (Optimizely's wording) and used it to add malicious JavaScript to customer projects. The customer projects were then served from Optimizely's CDN. Scott Helme (Report URI) analysed **1,611** Optimizely scripts and found **188** infected files belonging to **178** organisations. BleepingComputer used urlscan.io to confirm loads or load attempts on Zoom, CNN, Fox News, BBC, Salesforce, GitLab, KLM, Air France, American Eagle, Change.org and UNICEF USA. The payload `track.js` did four things. It swapped cryptocurrency wallet addresses on the page. It skimmed card number, expiry date and CVV to `card.php`. It loaded the **Coruna** and **DarkSword** iOS exploit kits for iPhones and iPads. It also collected cookies, URLs and screenshots. Some variants Base64-encode the URL and carry an embedded fallback copy in case the remote script is blocked. Optimizely closed the vulnerable path, removed the injected code, ended sessions, revoked tokens and blocked delivery at Cloudflare. By **21:52 UTC** only 1 of the 188 files was still malicious. Salesforce disabled Optimizely scripts across its preview and production instances as a precaution. Wallets in the script held about **$7,000**, but some of them predate the attack. The pattern is a Polyfill.io-style third-party script compromise, with an iOS exploit payload added.
**Action:** check whether any of your web properties load Optimizely Web Experimentation snippets, and pull the snippet versions you served on 16 Nov. Search CDN, proxy, DNS and CSP-report logs for `1688360[.]cc` (`/track.js`, `/card.php`). If checkout or wallet pages loaded the snippet, prepare for card-brand notification and review crypto withdrawals made that day for swapped destination addresses. Push iOS/iPadOS updates to managed devices. Consider Optimizely's snippet integrity check and a strict CSP or SRI for third-party tags.
Sources: [BleepingComputer](https://www.bleepingcomputer.com/news/security/optimizely-supply-chain-attack-delivers-malware-to-cnn-fox-news-bbc-salesforce-sites/), [GBHackers](https://gbhackers.com/hackers-inject-malware-into-178-major-brands-websites/), [Cyber Security News](https://cybersecuritynews.com/optimizely-websites-hijacked/)

### 1.2 N-able N-central 2026.4 Hotfix 3: 17 CVEs, the follow-up to the exploited 4EverAble2Shell chain (follow-up, ONGOING)
N-able's release notes, dated **16 Nov**, describe **2026.4 HF3** as a critical security update that builds on HF2. It fixes **CVE-2026-129271 to CVE-2026-129287**. The fixes include the following:
- unauthenticated ServerMMS/ServerMMS2 submission and read endpoints
- an MMS3 appliance auth bypass via a predictable passcode
- Audit Export syslog injection leading to root command execution
- path traversal in SIS GenericFiles leading to RCE
- two XXE bugs
- SSRF in Report Manager
- sendmail argument injection
- missing authorisation checks on ServerUI SOAP

The **Legacy API** configuration option has been removed, which permanently blocks legacy APIs. Remote control and the Intune integration stayed blocked at the time of writing. The 4EverAble2Shell chain needed Legacy API mode, and attackers used it to put XMRig on N-central servers, including servers already on HF2. N-able says Agents and Probes that are not upgraded "are susceptible to impersonation". CVSS scores and the mapping to Sean Bales' published PoCs are not yet available.
**Action:** upgrade on-prem N-central servers to **HF3** now, then upgrade **every Agent and Probe**. Hosted customers get the server update automatically but still need to upgrade agents and probes. Before upgrading, hunt for `nc_*` XMRig workers, unexpected root processes and new admin users. If you find them, treat the server as fully compromised and rotate every credential it stores.
Sources: [The Hacker News](https://thehackernews.com/2026/11/n-able-patches-17-n-central-flaws-as.html), [Huntress (background)](https://www.huntress.com/blog/n-able-disables-cloud-services-following-disclosure-of-able2shell-exploit-chains)

### 1.3 ScreenConnect CVE-2026-84869: guest "run file" spraying compromises MSP technician workstations (follow-up, ONGOING)
Huntress documented exploitation of **CVE-2026-84869** (CVSS **9.9**, in KEV since 11 Sep). A guest can trigger file-transfer actions that the *technician's* host client runs without confirmation, with elevated rights. From **20 Oct to 16 Nov**, Huntress counted about **688,000** guest "run file" requests for `update*.bat` files across **42** MSP servers. The attackers wait for a technician to join the session. They also join real customer sessions as an extra guest and push files to the technician. On **12 Nov**, one technician workstation was fully compromised in about **9 seconds**: a batch file installed a rogue, rebranded ScreenConnect client that connected to the attacker's relay. Path-traversal attempts to drop `Sync.bat` into Startup folders were also seen. Clients on 22.x, 24.2 and 25.8 were vulnerable. This is distinct from the SCKit/RMM+ activity covered last week, but it targets the same MSP population.
**Action:** update every technician host client and Access agent to **26.6.5+**, because a server-only update does not fix this. Until then, remove the `TransferFiles` permission. Hunt `Session.db` for `RanFiles` (EventType 85) and `SentFiles` (86) events from guests, blank-named sessions and `../` paths. On workstations, look for `%LOCALAPPDATA%\wclient_<8hex>\`, `%TEMP%\wupdate_<8hex>.msi` and a `Sync.bat` Startup entry. Block `masterdarky[.]com` / `194.15.36[.]33` (relay on port 8041) and the rogue client SHA-256 `f8871b1561d5c77c297378a7f49c84de52a01ff297395544f0e95d13ef972841`.
Sources: [Huntress](https://www.huntress.com/blog/cve-2026-84869-screenconnect-technician-exploitation)

### 1.4 AI agents now automate patch-to-exploit and AI-gateway key theft: Google GTIG and Amazon reports (NEW)
GTIG reports what it calls the first fully automated vulnerability discovery and exploitation it has seen. It found a multi-agent framework, `exploit_agent`, on an exposed staging server. The framework continuously diffs popular web apps before and after patches, drafts exploits, and runs them along with recon, brute-forcing and webshell deployment. Victims were French media, entertainment and education sites, and the actor is unnamed. GTIG cites the PHP2Shell bugs (**CVE-2026-109618/-109619**) as an LLM-assisted patch-diff case. It also documents LLMjacking that abuses the LiteLLM sandbox escape **CVE-2026-40217** to turn virtual keys into admin keys. In some incidents, fraudulent charges exceeded **$100k** in a single day. Amazon's MadPot honeypots captured ARTEX agents (moderate confidence: separate China-linked operators) hunting LLM gateways and AI builders between **3 Oct** and last week. Targets included One API/New API (an `isCliRequest` header auth bypass), LiteLLM default master keys, Langflow **CVE-2025-3248**, RAGFlow **CVE-2026-28797**, Dify, Open WebUI and Ollama. The agents also used SSRF to cloud metadata and secrets left in JavaScript, source maps and env files. They pooled stolen keys to pay for their own inference. Cloudflare reports **50+** AI pentest-framework families scanning its customers.
**Action:** inventory internet-exposed AI gateways and builders. Patch Langflow to **≥1.3.0**, RAGFlow to **≥0.25.0** and LiteLLM (CVE-2026-40217). Change default master keys and put admin UIs behind SSO or VPN. Rotate provider API keys stored in these apps and set budget and usage alerts. Add IP restrictions and expiry to Cloudflare API tokens (new tokens use the `cfut_` prefix). Shorten patch SLAs for internet-facing web apps.
Sources: [Google GTIG](https://cloud.google.com/blog/topics/threat-intelligence/agentic-threat-activity-crosses-a-significant-threshold), [AWS Security Blog](https://aws.amazon.com/blogs/security/amazon-threat-intelligence-observes-threat-actors-running-cybercrime-campaigns-with-artex-ai-agents/), [The Hacker News](https://thehackernews.com/2026/11/amazon-uncovers-ai-agent-campaign.html), [The Register](https://www.theregister.com/research/2026/11/16/google-ai-agent-turned-a-security-patch-into-a-working-exploit-with-no-human-help/5309926)

### 1.5 eMudhra CA distrust: Windows removal live, G1 issuance ends today, Apple 30 Nov (follow-up, deadline)
eMudhra's broken key ceremony truncated ECDSA private values to a single byte, which made **16** subordinate CA keys recoverable. eMudhra has revoked **eight more** intermediates and is leaving the public TLS business. **Microsoft removed all 10 remaining eMudhra roots** from Windows, Edge and Azure on **16 Nov**. eMudhra G1 issuance stops at **10:59 AEDT on 17 Nov**, and Apple ends trust in all eMudhra certificates on **30 Nov**. On macOS, command-line tools such as curl and git kept trusting the roots until **macOS 27.2.1, 26.7.3 and 15.8.3**.
**Action:** scan internal and external endpoints for certificate chains to eMudhra roots and reissue them from another CA now. Expect TLS failures on Windows clients and services that still present eMudhra chains. Update macOS fleets to the versions above.
Sources: [iTnews](https://www.itnews.com.au/news/emudhra-fiasco-widens-eight-more-cas-revoked-microsoft-pulls-trust-630303)

## 2. Vulnerability Watch
- **CISA KEV:** CISA has added nothing since **13 Nov**. The federal deadlines for Check Point Gaia **CVE-2026-123039** and UnrealIRCd **CVE-2026-114713** passed on **16 Nov**. Any unpatched instance should now be treated as overdue. For UnrealIRCd, upgrade to **6.2.7.1**. Versions 5.x and older are EOL and will get no fix. - **NoisyTCP CVE-2026-99288 (follow-up):** Red Hat rates the Linux kernel TCP race **Important (CVSS 7.5)**. The upstream fix landed on **3 Nov**. The researcher could crash VMs in seconds to minutes, but on bare metal a crash took about **14 hours**, and there is no sign of in-the-wild exploitation or of RCE. Containers do not isolate the host. Check your distro's kernel advisories and reboot internet-facing VM and container hosts first. [The Register](https://www.theregister.com/security/2026/11/16/noisytcp-bug-gives-linux-servers-a-remote-crash-problem-11-years-in-the-making/5310144)
- **Danfoss AK-SM800A refrigeration controllers (follow-up):** Midnight Blue (Carlo Meijer) reports **six** flaws that allow remote takeover **without login**. Five are in web handlers that run as root, and the sixth crashes the Strict-mode gateway. There is no CVE, no CVSS score and **no patch**: firmware **5.4.0** does not fix them, and BSI has walked back its statement that it does. The devices also lack secure boot. Remove internet and cellular-modem exposure and use VPN-only remote access. [The Hacker News](https://thehackernews.com/2026/11/six-unpatched-danfoss-refrigeration.html)
- **Copeland/Dixell XWEB EVO (follow-up):** exploitation is so far opportunistic. One IP sent **125** requests for **CVE-2026-124014**, and a second IP sent four probes for **CVE-2026-124010**. Both flaws affect only pre-2021 firmware. Onyphe counts about **2,000** exposed XWEB EVO hosts. VulnCheck says these scans are not the IRGC-attributed October campaign. [SecurityWeek](https://www.securityweek.com/hackers-probe-newly-disclosed-flaws-in-copeland-refrigeration-controllers/)
- **GeoVision GV-VMS exploited for cryptojacking:** between **8 and 10 Nov**, attackers compromised Windows hosts at **13** organisations through internet-exposed GV-VMS **17.4.8.0**. GeoVision's April 2026 advisory lists three unauthenticated RCE flaws in WebCam Server, fixed in **V17.4.8.58**, and no CVE has been named. The attackers used a BYOVD driver to tamper with antivirus and IFEO hijacks to stop security tools from starting. A loader that finds its servers via BitTorrent DHT and PKARR then fetched XMRig. Update GV-VMS, take it off the internet, and hunt for shells spawned by GeoVision services. [Huntress](https://www.huntress.com/blog/geovision-camera-software-xmrig-cryptominer), [Help Net Security](https://www.helpnetsecurity.com/2026/11/16/geovision-camera-software-vulnerabilities/)

## 3. Incident Watch

Exposed data includes some customers' **NIOS configuration backups**, which can contain DNS/DHCP configuration, Grid databases and reporting logs, as well as employee and dependent data including SSNs and direct-deposit details. Infoblox says its products, cloud services and software updates were not involved. No actor is named and no numbers have been given. Customers should ask whether their NIOS backups were affected and, if so, review any secrets or topology those backups expose. Fandango has not given a victim count, and nothing links this incident to Optimizely. [BleepingComputer](https://www.bleepingcomputer.com/news/security/fandango-says-hackers-stole-payment-card-details-from-checkout-pages/)
- **Fireworks AI fallout: Uber and Cursor (follow-up):** Uber's state filings put the 7 Oct theft of driver data (licence images, DOBs, ID numbers) at **149,346** people. The data was stolen through compromised credentials at a vendor that Uber confirmed to TechCrunch was Fireworks AI. New details on Cursor: a Cursor access key issued to Fireworks gave the attacker access to unredacted credentials. With those, the attacker served trojanised copies of the Claude Code extension (**2.1.312/2.1.313**) from Cursor's marketplace cache for about **11 hours**, reaching up to **5,000** users. Cursor warns that uninstalling the extension alone may not be enough. Notion was also affected. [SecurityWeek (Uber)](https://www.securityweek.com/uber-data-breach-impacts-150000-people/), [SecurityWeek (Cursor)](https://www.securityweek.com/cursor-supply-chain-attack-started-at-fireworks/)

Attempts to use those credentials are under investigation. **4,222** Fugaku users and **375** Rikyu users are at risk, and Fugaku is offline. Research institutions that federate with RIKEN users should force password resets. They come from `moments-notice[.]com`, `planetmaison[.]com` and `newbooker[.]com`, redirect through `reallifeaccounting[.]com`, and use subjects of the form "Outage - XXXXXX". ## 4. Threat Watch
- **TGR-STA-0049 (REF7707 / Earth Alux / Ink Dragon), HTTP/3 RATs against Southeast Asian governments:** Unit 42 details **PerfectPioneer**, a Go RAT seen since Jul 2025, and **KUKURAT**, a modular C++ backdoor seen since Mar 2026. Both use **HTTP/3 (QUIC over UDP/443)** for C2 with HTTP/2 fallback and share the endpoints `/agent/register`, `/heartbeat`, `/tasks` and `/result`. The cluster steals foreign-policy and internal-politics documents, and one lure impersonated a Myanmar election notice. Example C2 domains are `cloudflacecdn[.]com`, `police.gr[.]com`, `ads-edge[.]com` and `wkuyda[.]com`. Where you cannot inspect QUIC, consider blocking or logging outbound UDP/443 from servers. [Unit 42](https://unit42.paloaltonetworks.com/custom-rats-target-southeast-asia-governments/)
- **SilentAir and LIMINAL PANDA, telecom espionage:** Enea describes **SilentAir** as a new state-level actor (high confidence) with low-confidence China links. Using compromised operator nodes in at least six Asian countries, it runs SS7/Diameter location-update attacks to intercept calls, SMS and 2FA codes, mainly against **Taiwanese** political figures, and uses silent SMS to test interception. LIMINAL PANDA's **GTPDoor v3** now hides in GTP-U and captures traffic with libpcap. Enea sees 5 to 10 infected operators, mostly in Asia, Africa and Latin America. [Security Affairs](https://securityaffairs.com/203099/apt/silentair-and-liminal-panda-target-telecom-networks-to-spy-on-subscribers.html)
- **Phantom53, a ClickFix implant built with an AI coding agent:** SOCRadar describes an operation active since **Aug 2026**. It uses about 1,000 personalised lure pages on Cloudflare Workers, generated by the "XaocMail" platform, to deliver an MSI through msiexec. The implant carries C2 commands in IPv6 answers to DNS AAAA queries over public DoH resolvers, with a weekly SHA256 DGA on `.xyz` as fallback, and loads Havoc in memory. Stealer modules target password managers, VPN configs, AI tool secrets and SSH/GitHub tokens. The operators' repository contained `.claude/` task files and Russian-language agent prompts. Targets are in Brazil, Peru, India, Indonesia and Spain. Example IOCs are `185.224.132[.]148` and `145.63.138[.]67:8125`. [GBHackers](https://gbhackers.com/phantom53-malware-attack/)
- **Retadup worm returns with CoffeeLoader:** Kaspersky reports that the USB/LNK worm, which French police dismantled in 2019, is active again on re-registered C2 domains such as `alphanoob[.]com` and `newminersage[.]com`. It now delivers **CoffeeLoader** through a patched 7-Zip DLL and an Armoury packer variant that uses OpenGL for decryption. About **15,000** blocked attempts were recorded in Q1 to Q3 2026, mostly in Peru, Angola, Russia and Bolivia. [Securelist](https://securelist.com/retadup-delivers-coffeeloader/121908/)
- **BO Team (Black Owl / Hoody Hyena), Log4Shell to code-signing server:** Kaspersky ICS CERT describes a months-long intrusion, contained in 2025, at a Russian software developer. The group exploited Log4Shell on an unpatched **vCenter 7.0.3**, planted a GSocket backdoor through a cron job disguised as "pgcache", and reached GitLab CI/CD and the build-signing server. That access was enough for a supply-chain attack. The lesson is that legacy vCenter remains an initial-access path. [The Hacker News](https://thehackernews.com/2026/11/bo-team-exploits-log4shell-in-vmware.html)
- **AI-profiled infostealer log marketplace:** Hudson Rock reports an unnamed shop that writes LLM-generated profiles of each infected victim (employer, valuable accounts) and offers natural-language search, prices from **$0.25**, and logs as fresh as 24 hours. The operator's claim of "a billion+ accounts" is unverified. Treat infostealer exposure of corporate SSO, VPN and cloud sessions as an incident trigger. [Help Net Security](https://www.helpnetsecurity.com/2026/11/16/ai-powered-infostealer-marketplace-victim-profiles/)
