## 1. Risk Watch

### 1.1 APT29 watering holes push n-day exploit chains to iOS and Android; Apple CVE-2024-27834 added to KEV (NEW)
**The campaign (Sekoia, 4 Nov):** Sekoia attributes it to APT29 (SVR, Midnight Blizzard) with moderate to high confidence. Sekoia detected it in mid-October.
- **Delivery:**
  - JavaScript injected into compromised sites in the US, Ukraine, Czech Republic and Bulgaria.
  - Reverse-proxy lookalike domains, for example `america250[.]holiday` and `theowo[.]club`.
  - Code served through the Plerdy tracker (`a.plerdy[.]com`), which runs on thousands of mostly Ukrainian sites, from **27 Aug to 3 Sep**.
- **Filtering:** a fingerprinting script ("UltimateFingerprinter") screens visitors before any exploit is served.
- **Exploit chains (all patched n-days):**
  - **iOS 16.0–17.4:** **CVE-2025-43529** plus **CVE-2024-27834**, to steal Safari and app cookies.
  - **iOS 18.5:** a DarkSword-based chain (CVE-2026-20700, CVE-2025-14174, CVE-2025-43510, CVE-2025-43520) that exfiltrates messages, Keychain, Wi-Fi keys, photos and Health data.
  - **Android Chrome 139–145:** **CVE-2026-3910** plus **CVE-2025-27038**, delivering the "AndroSnitch" stealer.
  - None of the chains persist on the device. Sekoia says fully updated devices are not affected, and suspects the exploits came from a commercial surveillance vendor.
- **CISA:** added **CVE-2024-27834** (CVSS 5.5, PAC bypass) to KEV on **4 Nov**, due **18 Nov**.

Action:
- Enforce minimum OS versions through MDM: current iOS/iPadOS 18 or 26 builds, and current Chrome on Android. Devices still on iOS 16–17.4 or Chrome 139–145 are fully exposed.
- Block and hunt the infrastructure in DNS and proxy logs: `static.flux-telemetry[.]com`, `edge-ord.clouds-stacks[.]com`, `ad.starx-net[.]com` (port 8881, path `/telemetry/v12`), `ads-it-assets[.]com`, `cdn.adv-static[.]com`, `wpvortex-mod[.]com`, `assets-int[.]com`, `adsprism-stat[.]com`, and the IPs 109.104.106[.]107, 95.133.231[.]28 and 195.58.140[.]105.
- Treat sessions from any device that visited the listed sites as stolen. Revoke web and app sessions and rotate Wi-Fi PSKs.

Sources: [Sekoia](https://www.sekoia.com/blog/poisoned-source-apt29-watering-holes-targets-mobile-devices-with-n-day-exploits) · [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) · [The Hacker News](https://thehackernews.com/2026/11/hackers-exploit-patched-apple-flaw-to.html) · [Help Net Security](https://www.helpnetsecurity.com/2026/11/04/apt29-watering-hole-mobile-devices-n-day-exploits/)

### 1.2 Zyxel GS1900 CVE-2026-107441: the zero-day behind ~1,000 compromised switches (follow-up)
**What changed:** Zyxel's 3 Nov advisory covers an unauthenticated out-of-bounds write in the GS1900 web CGI that can run OS commands. It is now reported as the actual root cause of GreyNoise's mass compromise of **996** switches in **48** countries around **17 Aug**.
- **Why earlier patching did not help:** those attacks had been blamed on **CVE-2026-7273** (in KEV since September), which Zyxel fixed in June. Binarly found the exploit still worked on all ten June-patched firmware builds.
- **Timeline:** Zyxel confirmed the new bug on 11 Oct and shipped fixes on 22 Oct.
- **What the attacker took:** configurations, network details and hashed root credentials. GreyNoise linked the actor to a suspected Chinese-speaking cluster.
- **Severity dispute:** Zyxel describes a LAN-adjacent attacker; Binarly describes remote root.
- **Affected and fixed:** ten models (GS1900-8/8HP/10HP/16/24/24E/24EP/24HPv2/48/48HPv2) on **2.90(xxxx.2)C0 and earlier**, fixed in **2.90(xxxx.3)C0**.

Action:
- Upgrade every GS1900 to the .3 build, even if you applied June's CVE-2026-7273 fix.
- Take the web management interface off the internet and off user VLANs.
- On any switch that was exposed, treat the configuration as stolen: rotate admin and SNMP/RADIUS secrets, review the configuration for unexpected changes, and replace factory-default credentials (more than half of GreyNoise's victims still used them).

Sources: [Zyxel advisory](https://www.zyxel.com/global/en/support/security-advisories/zyxel-security-advisory-for-out-of-bounds-write-vulnerability-in-gs1900-series-switches-11-03-2026) · [BleepingComputer](https://www.bleepingcomputer.com/news/security/zyxel-fixes-zero-day-exploited-to-hack-nearly-1-000-network-switches/) · [Help Net Security (Sept. background)](https://www.helpnetsecurity.com/2026/09/22/zyxel-switches-cve-2026-7273-vulnerability-exploited/)

### 1.3 Debian/Ubuntu APT CVE-2026-109518: a network attacker can swap verified packages (NEW)
**The flaw (disclosed 4 Nov):** reported by Max Justicz. An attacker who can alter HTTP traffic between APT and its mirror (a malicious mirror, proxy or on-path position) can use redirects and ordinary temporary server errors to force APT to retry downloads. During the retry, a package that has already been verified is replaced with the attacker's, which then runs as root at install time.
- **Severity:** Ubuntu rates it high (CVSS 4.0 **7.7**); the APT developers call it critical.
- **Exposed by default:** Debian 12+ and Ubuntu 22.04+, where download retries are on. Debian 11 and Ubuntu 20.04 are exposed only if `Acquire::Retries` was set.
- **Fixed APT versions on Ubuntu:**
  - 26.10: **3.3.3ubuntu0.1**
  - 26.04: **3.2.1ubuntu0.1**
  - 24.04: **2.8.4ubuntu0.1**
  - 22.04: **2.4.15ubuntu0.1**
- **Debian:** stable fixes are out; Debian 11 has **2.2.5** from upstream; testing was still vulnerable on 4 Nov.
- **Exploitation:** none reported in the wild.

Action:
- Update the `apt` package first, as its own step, before any other package runs. The bug is triggered during installs, so updating apt in the same run as other packages leaves that run exposed.
- Use HTTPS mirrors where possible, and lock down mirror and proxy paths in CI and image-build pipelines.
- Check older systems and scripts for `Acquire::Retries` settings.

Sources: [The Hacker News](https://thehackernews.com/2026/11/debian-and-ubuntu-apt-flaw-lets-mitm.html)

### 1.4 Rails Active Storage + ImageMagick: unauthenticated file write, CVSS 9.8 (NEW)
**The flaw:** advisory **GHSA-f3w6-w445-fwh9** (no CVE yet), reported by RyotaK of GMO Flatt Security. A crafted SVG upload reaches ImageMagick's MSL coder through the Active Storage analyzer. Attaching the file is enough to trigger it.
- **Impact:** attackers can write arbitrary files on the server. On apps using the Disk storage service they can also read files, including `secret_key_base`, which can lead to code execution.
- **Who is affected (all three must apply):**
  - The app uses `:mini_magick`, which is the default under `load_defaults 6.1` or earlier.
  - The ImageMagick policy does not block these coders (Debian's and Ubuntu's default policies do not).
  - The app accepts uploads from untrusted users.
- **Fixed:** **8.1.4.1** and **8.0.5.2**. These releases fix **21** security issues, including GHSA-v924-7rp8-4mxh (CVSS 8.8, decoder selection from the filename extension) and ship a restrictive ImageMagick policy, which requires mini_magick **5.1+**. Older series get no fix.
- **Exploitation:** none reported so far.

Action:
- Upgrade, then confirm the policy loads with `bin/rails runner 'puts MiniMagick.identify { |i| i.list "policy" }'`.
- If you cannot upgrade, copy the blocks from Active Storage's `policy.xml` into `/etc/ImageMagick-*/policy.xml`. At minimum block the MSL and Ghostscript coders and the `gs` delegate.
- On Disk-storage apps that took untrusted uploads, rotate `secret_key_base`, the master key and every credential the process can read.
- Rails 8.0 security support ends on **7 Nov**.

Sources: [The Hacker News](https://thehackernews.com/2026/11/critical-rails-flaw-lets-attackers.html) · [Dark Reading](https://www.darkreading.com/application-security/critical-rails-bug-derail-vulnerable-servers)

### 1.5 Refrigeration sabotage hits French blood plasma storage through provider Coolworld (DEVELOPING)
**What happened:** on the night of **1–2 Nov**, the supervision and control systems for cold rooms at **three** EFS (Établissement français du sang) sites, notably in Bourgogne-Franche-Comté, were changed remotely.
- **The changes:** temperature and defrost thresholds were set very high. Le Canard enchaîné reported settings of up to 110 °C on rooms normally kept at −30 °C.
- **Impact:** alarms and an on-call technician caught it, plasma was moved to other sites, and EFS says no products were lost and there was no health impact. ANSSI and the Health Ministry are investigating.
- **Provider:** Le Canard enchaîné named the refrigeration provider as **Coolworld**, a Dutch temperature-control rental firm active in France, Germany, Ireland, the Netherlands and the UK.
  - Coolworld cites an incident involving "remote monitoring software" and a third-party component it does not control, affecting a limited number of units.
  - The component has not been named.
- **Context:** this follows the 2 Nov supermarket wave in at least nine EU countries plus the UK. No group has claimed it, and no link has been proven.

Action:
- Ask every refrigeration, cold-chain and building-management contractor, including rental units, how their remote monitoring is reached and which third-party software it uses.
- Put that software behind a VPN or allow-list, change default credentials, and alert on setpoint or defrost changes outside maintenance windows.
- Healthcare, pharma and food operators should also make sure alarms work independently of the remote platform, for example local temperature alarms.

Sources: [franceinfo](https://www.franceinfo.fr/internet/securite-sur-internet/cyberattaques/une-cyberattaque-touche-des-installations-frigorifiques-utilisees-par-l-etablissement-francais-du-sang-sans-impact-sur-les-echantillons-conserves_8267426.html) · [Infosecurity Magazine](https://www.infosecurity-magazine.com/news/france-blood-service-cyberattack/) · [The Register](https://www.theregister.com/security/2026/11/04/cyberattack-on-french-plasma-stores-is-enough-to-make-your-blood-boil/5307519)
