## 1. Risk Watch

### 1.1 SonicWall SonicOS SSL-VPN SAML/MFA bypass CVE-2026-19868 (follow-up, ONGOING)
- **Advisory:** SonicWall advisory **SNWLID-2026-0014** names the affected models: Gen7 TZ, NSa, NSsp and NSv on **7.3.3-7015** and earlier, and Gen8 TZ, NSa and NSv on **8.2.2-8015** and earlier.
- **Exposure:** only SSL-VPN with SAML login enabled is exposed.
- **Exploitation:** SonicWall says it investigated a report of "potential exploitation", and the CVE is in KEV with a **20 Nov** deadline. Neither the vendor nor CISA has described the attacks, and it is unknown whether this was a zero-day.
- **Other fixes in the same release:** two management-interface flaws rated **CVSS 8.8** (permissive cross-domain policy and session validation) that can be abused without authentication. Also three pre-authentication overflows in SSL-VPN and TACACS+ that cause denial of service.
- **Separate SonicWall flaw:** **CVE-2026-102255** has been targeted since last month and is still not in KEV.

**Action:**
- Upgrade to **7.3.4-7013** or **8.2.3-8015**. There is no workaround.
- Until then, consider turning off SAML-based SSL-VPN login.
- Review SSL-VPN logs since October for logins that skipped the SAML/MFA step.
- Restrict the management interface to trusted networks.

Sources: [SecurityWeek](https://www.securityweek.com/sonicwall-patches-exploited-sonicos-bug-that-weakens-vpn-logins/), [Security Affairs](https://securityaffairs.com/202581/security/u-s-cisa-adds-sonicwall-sonicos-sslvpn-flaw-to-), [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

### 1.2 WordPress core upgrade-window RCE CVE-2026-119977: more than 240,000 attempts (follow-up, ONGOING)
- **Volume:** Wordfence has now blocked more than **240,000** exploit attempts since **28 Oct**. They peaked **29 Oct–1 Nov**, with more than **74,000** on 30 Oct.
- **The flaw:** a time-of-check/time-of-use race against predictable, web-accessible staging folders created during full-package core upgrades. **CVSS 8.1**, affecting **4.7–7.1.3**.
- **The attack:** attackers request staged installer files such as `/wp-content/upgrade/wordpress-6.9.11/setup-config.php` to hijack the installation, create an administrator and upload PHP.
- **How to read the numbers:** they count blocked attempts, not compromises. Success requires hitting the short window while an upgrade is running.
- **The fix:** **7.1.4** randomizes the staging folder. However, the update that installs it runs the old updater code one last time (see Friday's briefing).

**Action:**
- Confirm sites are on **7.1.4+**.
- Search access logs for any external request to PHP files under `/wp-content/upgrade/`. Legitimate upgrades never make such requests.
- Audit for administrator accounts and PHP files created during upgrade windows.
- Top sources to hunt or block: **103.59.160.171**, **2001:df1:e8c0::106b**, **51.89.103.78**.

Sources: [GBHackers (Wordfence telemetry)](https://gbhackers.com/exploit-wordpress-core-over-240000-attack/), [Wordfence](https://www.wordfence.com/blog/2026/11/attackers-actively-probing-for-upgrade-window-rce-vulnerability-in-wordpress-core/), [The Hacker News](https://thehackernews.com/2026/11/installing-fix-for-exploited-wordpress.html)

### 1.3 Claude Code "Yes, and don't ask again" leaks secrets into `.claude/settings.local.json` (NEW)
- **The issue:** Apiiro found that approving a shell command with "don't ask again" saves the exact command, including any inline password or token, in plain text in `.claude/settings.local.json`.
- **Why it ends up public:** Claude Code adds the file only to the local global git excludes, not to the project's `.gitignore`. In **539 of 1,105** traced repos, a commit co-authored by Claude changed the file.
- **Scale:** **104,185** copies are public. **1,122** of them contain **1,379** secrets, including **379** database passwords, **43** SSH logins, **42** GitHub, GitLab and npm tokens, and **23** AWS keys.
- **Including history and related files:** counting history, forks, shared `settings.json` files and agent chat logs, the total is **2,539 secrets in 1,994 repos**, belonging to **63** organizations.
- **Detection gap:** gitleaks and TruffleHog missed **215** of the files, mostly passwords inside commands (`PGPASSWORD=`, `sshpass -p`, `mysql -p`).
- **Vendor response:** related GitHub issues, starting with **#5544** in August 2025, were auto-closed as "not planned". The researchers say Anthropic has not replied, and no fix has been described.
- **Reliability:** all of this comes from one research team, as relayed by several outlets. We could not locate Apiiro's original write-up.

**Action:**
- Search your organization's repos and git history for `.claude/settings.local.json` and `.claude/settings.json`. Treat `.cursor/`, `.gemini/` and `.specstory/` the same way.
- Rotate every secret these files have ever held, before cleaning up.
- Untrack the file with `git rm --cached .claude/settings.local.json` and add it to `.gitignore` templates.
- Make sure pre-commit and CI secret scanning catch passwords inside commands.
- Keep secrets out of approved commands by using environment variables.

Sources: [The Hacker News](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html), [DataBreaches.net (Apiiro relay)](https://databreaches.net/2026/11/07/coding-agents-copy-your-secrets-to-a-hidden-file-thousands-are-on-github/), [Cyber Security News](https://cybersecuritynews.com/claude-codes-yes-and-dont-ask-again/)

### 1.4 ARTEX agentic attack framework: Hunt.io maps the infrastructure, Censys counts 800+ exposed consoles (ONGOING)
- **Hunt.io's mapping:** it charted the operator behind the Sept–Oct breaches of **seven South Korean financial institutions**, which exposed about **66–67k** people and **~2,200** companies.
- **The operator's setup:** Claude Code **2.1.221** was used as the harness, with no connection to Anthropic. It was routed through Claude Code Router and the reseller `xcai[.]pro` to **DeepSeek v4.1 Flash**, with GLM and Grok as backups. Shims named `ds-models-shim.py` and `xcai-effort-shim.py` made the routing work.
- **What else was found:** **19** custom attack skills, a staged JNDI/LDAP exploitation kit on port 8001, and tooling aimed at cryptocurrency-exchange withdrawals. The link between that tooling and the Korean breaches is unconfirmed.
- **Attribution:** CrowdStrike assesses with moderate confidence that a single financially motivated Chinese-speaking individual was behind it. Hunt.io's findings are consistent with that but do not independently attribute it.
- **Exposed consoles:** separately, Censys found more than **800** ARTEX deployments reachable without authentication, some exposing implants. Not all are malicious, since authorized testers also run ARTEX.
- **Wider context:** this adds to Microsoft's Storm-3358 reporting (financial sector) and the WorkOS and Chainstack incidents.

**Action:**
- Block and hunt for **38.244.50.120**, **23.248.226.250**, **154.201.79.246:443**, **130.94.31.86:18888** and **156.251.11.39**.
- Watch for outbound LDAP/JNDI activity and DNS callbacks from internet-facing applications.
- Remove anonymous file-upload and SSRF exposures on internet-facing applications.
- Put admin and model-gateway services behind a VPN or allowlist.

Sources: [Security Affairs (Hunt.io)](https://securityaffairs.com/202607/ai/inside-artex-ai-hacking-tools-exposed-servers-and-south-korean-bank), [TechCrunch (Censys)](https://techcrunch.com/2026/11/06/hundreds-of-artex-ai-hacking-tools-found-publicly-exposed-to-the-web/), [Cloud Security Alliance research note](https://labs.cloudsecurityalliance.org/wp-content/uploads/2026/10/CSA_research_note_artex_agentic_pentest_bank_breaches_20261009-csa-styled.pdf)

### 1.5 OpenSSH "SSHole" CVE-2026-123158 on musl/Alpine (follow-up, ONGOING)
- **Status:** nothing new since Friday. Exploitation was seen within hours of disclosure, including root on an Alpine honeypot, but the evidence comes from one vendor and one sensor. The flaw is still not in KEV.
- **The bug:** on musl builds without PAM, any **257–1,024-byte** password logs in to accounts whose shadow hash is `*`. Fixed in **OpenSSH 10.6p2**.

**Action:**
- Inventory Alpine hosts and musl-based containers and appliances (OpenWrt, Buildroot, Yocto) running password-enabled sshd.
- Update to **10.6p2**, or set `PasswordAuthentication no`.
- Hunt auth logs for successful password logins to system accounts.

Sources: [Help Net Security](https://www.helpnetsecurity.com/2026/11/06/openssh-sshole-cve-2026-123158-exploitation/), [The Hacker News](https://thehackernews.com/2026/11/hackers-exploited-openssh-sshole-flaw.html)

## 3. Incident Watch
- **Crédit Mutuel Arkéa, France (developing):**
  - **What happened:** an attacker came in through a **service provider's platform** and used the bank's own account to wire funds to other banks, where they were converted to USDC/USDT stablecoins.
  - **Amount:** ZachXBT estimates **€118M (~$133M)**. Arkéa confirms only "the order of magnitude" and says some funds were blocked. ZachXBT says about **$30M** was laundered by 3 Nov because nothing had been disclosed.
  - **Customers:** the bank says customer assets are unaffected and rules out Fortuneo as the entry point. It has not named the provider and warns customers of follow-on phishing.
  - **Watch for:** the provider's identity, and whether other banks use the same provider.

## 4. Threat Watch
- **AI-assisted CEO and lawyer impersonation fraud (SDNY indictment):**
  - **Charged:** Jacob Soall (Spain), Sharon Hazan and Guy Sheetrit (Israel), with wire fraud, money laundering and aggravated identity theft.
  - **The scheme:** about **$129M** stolen in 2024–2026. Co-conspirators used AI-spoofed voices and video of real executives and law-firm lawyers to talk employees into "confidential" transfers.
  - **Victims:** two US hospitals, a Rhode Island bank and a UK tech firm (**$11.5M**), among others.
  - **Status:** arrests were made in Spain and the UK, and extradition is pending.
  - **Lesson:** require out-of-band callback verification for any executive-initiated wire, whatever the video or voice evidence.
  - [The Record](https://therecord.media/ceo-spoofing-scammers-charged)
- **ARTEX open directories as a recurring opsec failure:** CrowdStrike, Hunt.io and Censys all built their findings on operators leaving open directories and unauthenticated consoles, and these exposed Claude Code session histories, skills and credentials. Proactive scanning for ARTEX console titles and certificates is now a practical hunting method (see 1.4). [Security Affairs](https://securityaffairs.com/202607/ai/inside-artex-ai-hacking-tools-exposed-servers-and-south-korean-bank)
- **Service-provider path into banks:** the Arkéa heist (Section 3) fits a pattern of supply-chain fraud that went straight to money movement, following last week's Group-IB reporting on infostealer-enabled bank intrusions.
